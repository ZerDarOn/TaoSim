# 地图观察、语义缩放与旅行响应改进

> 日期：2026-09-08
> 状态：M0/M1 保留；R0–R6 已完成自动门检与隔离真实浏览器复验。
> 关联：[修仙生活与可玩性实施方案](cultivation-life-playability-implementation-plan.md)
> 本轮优先级：在现有 P1/P2 成果上优先执行 M0–M3，再回到主方案未完成阶段。保留原范围、未达项和所有未提交改动；不得把旧动态空间 Phase 0–7 与新生活 P0–P7 混为同一完成报告。

## 1. 用户反馈与目标

用户认可 NPC 路线意图的可观察性，希望可以开关，并增加其他观察方式；前往地点有卡顿；希望放大地图后能进入更详细的区域地图。

交付目标：旅行点击有及时反馈；路线按需显示；缩放时逐渐看清现有真实区域、道路、人物与场所。观察操作不移动玩家、不推进时间、不改变结算，不通过关闭世界模拟制造流畅假象。

## 2. 当前证据与待测假设

只读确认 MapPanel 的地图变换目前以 panOffset 平移为主；npcTravelOverlays 枚举活动旅行人物并按大陆筛选，模板批量绘制路线。附近时间线过滤世界事件集合。useWorld 每次推进复制玩家与整个世界快照、同步调用 TimeAdvanceService、整体发布结果并写日志。
这些是测量候选，尚不能断言哪个是实际卡顿主因。前期快照转换修复了 Vue Proxy 复制异常，不得为优化直接撤回而再次传 Proxy。

M0 必须区分：点击/路径计划、权威推进（含月界）、快照转换、事件导入/存储、Vue 更新、SVG 渲染及浏览器长任务；用户说“前往卡”不能只用 Node 十年快进测试代替。

## 3. 路线与观察图层

- 路线模式：关闭 / 选中与关注 / 全部可知。默认“选中与关注”；上帝模式可选全体，角色模式遵守个人感知与已知情报。
- 玩家自己的当前行程与目的地进度单独表达，不因隐藏 NPC 路线而失去导航。
- 人名模式：聚合 / 选中显示 / 可知范围全部；密集点聚合，悬停/选择再展开。
- 第一批其他观察层：人物活动与分布、道路/通行状态、已有资源/灵气、势力边界、既有危险/空间特征。只对具有实际权威数据和知识来源的层提供可用开关；没有数据不要制造热力图或虚构资源。
- 图层开关关闭时不生成昂贵渲染数组与路径，不只设 CSS 隐藏；不可因此停止对应 NPC 行动。
- 设置作为显示偏好保存，按区域保存合理的视角；不得覆盖 SpatialAddress/TravelState 或跨存档继承探索知识。

## 4. 地图缩放与细节展开

### 4.0 用户试玩后的架构纠偏

旧首版把同一张 Region SVG 放大、隐藏文字并叠加一个不可交互近景，视觉上变大但空间层级没有变化。该实现不满足“进入详细区域地图”，旧 M2 的完成判断作废。

现明确区分两种操作：`cameraZoom` 只改变观察尺度和信息密度；`focusedSpatialNodeId` 才表示进入包含树的下一层空间。下钻不移动玩家、不推进时间；在详细地图内前往节点才创建真实 TravelState。放大不是无限生成层级，当前对已有权威数据的天机城与青云宗开放完整下钻。

### 4.1 基础交互

提供滚轮/触控板缩放、加减按钮、适配视野、回到人物（上帝模式为回到观察焦点）。以光标所指地点为缩放锚点，拖动平移，保留选择与移动分离规则。缩放/拖动不误触旅行；地图外滚轮保持页面行为。
缩放范围有界；按钮作为触控和键盘备用；视角偏好节流保存，避免每帧同步写 localStorage。

### 4.2 语义尺度

| 视图 | 展示内容 |
|---|---|
| 宏观 | 聚落、地理、主干道路、势力与人物聚合；次要名字和路线收起 |
| 区域 | 当前焦点周围实际道路、地形、路线进度、可见 NPC、资源与危险 |
| 地点 | 已存在聚落/场所及连接，选中人物的行为和可用交互 |

第一处完整近景采用天机城及现有周边空间节点。复用包含树、连接图和真实空间数据；放大同一组世界事实，不能只把原 SVG 放大后改标题宣称区域地图完成。

详细几何不足时，用权威节点与道路的稳定布局表达，并明确实际支持范围；若需要补充详细区域坐标/几何，作为可复现、可保存的空间数据扩展，迁移保留旧人物位置与路线，不在 UI 临时生成另一张世界。

视图切换设置不同进入/退出阈值，避免滚轮临界点反复切图；跨区域后保持选中对象/世界锚点，使用明确坐标变换，不能混用不同 LocalArea 的 q/r。提供可理解的层级提示与缩回入口。

角色可以缩放已知地图，但不能因此发现未探索地点、获知远方秘密计划。上帝可改变观察焦点，仍不改变人物事实。当前战斗地图缩放不是本任务的替代实现。

### 4.3 连续旅行协议

- 路线由有序 `TravelRouteSegment` 构成，保存当前段、段内距离、累计距离、上次推进时刻和计划代次；旧 v9 缺少这些可选字段时可从剩余距离与开始时刻恢复。
- 玩家与 NPC 使用同一个途中位置求值器。普通移动按距离/速度推进经过的格或道路节点，不在 ETA 时从起点闪到终点。
- 主动暂停冻结路程；继续只适用于暂停。路线受阻必须重规划、等待道路恢复或折返，不能借“继续”穿过失效连接。折返从当前段内位置开始，已经消耗的世界时间不返还。
- 每段终点是调度检查点；调度器一次消费一个最早唤醒，使途中新增的更早事件不会被已经批量取出的晚事件越过。无关空间变化不再打断全世界行程，只有剩余路线本身失效才中断。
- 普通旅行已有首个真实道路接触实例：两条连续行程在同一连接上求实际接触分钟，只有具名 NPC 的寻仇、挑战或社交意图可创建相遇；统一时钟停在该分钟，选择前相遇与双方暂停行程可保存。动态绕路和更多相遇类型仍未实现。

## 5. 性能与正确性

- 先测量后优化：同一世界快照与路线比较路线关闭/关注/全部，区域缩放前后，以及普通推进与跨月推进。
- 优先可见范围筛选、渲染聚合、空间索引、稳定派生缓存、日志查询和导入批处理、视角写入节流。缓存失效以真实状态版本为依据。
- 若测出世界推进占用主线程，选择现有可中断批处理或 worker 方案；先规定单写者、版本化提交、暂停/读档取消旧请求，防止过期结果覆盖新世界。不能仅在同步工作前加 loading 或 Promise 就宣称解决。
- 保留快照边界或以经验证的安全投影替换。禁止通过吞事件、削减人物身份、跳过具名战斗或放宽时钟一致性提速。
- 只绘制可见对象；隐藏图层前后相同输入应产生相同世界领域结果。拖动缩放不能触发全世界重新生成、推进或持久化。

## 6. 实施与退出标准

| 阶段 | 工作 | 退出证据 |
|---|---|---|
| M0 复现与测量 | 找到当前真实入口，建立隔离试玩档，对旅行启动/途中推进/到达分别计时；记人口、事实量、可见路线数量、浏览器长任务 | 有基线、主要耗时分布及可重复路线；不凭推测先重写 |
| M1 路线与观察设置 | 路线三档、人名聚合、实际可用图层及偏好保存；首次缩放按钮与视角状态 | 开关可用、选中路线清楚、关闭无残留渲染、NPC 继续行动、角色知识不泄漏 |
| M2 区域细节缩放 | 完整锚定缩放、语义视图、天机城及周边详细节点道路、坐标映射、返回焦点 | 从宏观放大到区域/地点再缩回，观察同一人物与行程；期间位置、日期、资产不变；不出现假地点 |
| M3 响应优化与真实 UI 回归 | 对 M0 主因实施必要优化，验证暂停/保存/加载不会被后台结果覆盖；复测整条路线 | 相同条件前后对比、明确余留卡点、P1/P2 与旅行存读档不回归；实际浏览器可操作 |

建议体验预算（作为目标，不是已有测量）：单次旅行点击可见反馈在 100ms 内；连续缩放/平移大多数帧不超过约33ms，不出现持续超过100ms的交互冻结。长旅行/跨月计算需显示真实进度并保留界面响应；硬件、样本次数和未达项必须报告，不把调低人口得到的数字当同条件优化。

至少验收：滚轮与按钮缩放；缩放锚点；平移后格子选择/右键移动正确；图层偏好重开保持；角色/上帝信息范围；密集人物与离屏路线；旅行中缩放/隐藏路线/切页/保存/加载/继续；同条件开关图层世界结果一致；视图阈值不抖动；已有战斗与出生入口无回归。

## 7. 交付与协作

在主实施账本增记 M0–M3，精确区分实现、自动检查与浏览器验收。修改相关模块后跑必要测试，阶段结束测真实 UI，避免逐文件全量测试。最后记录新旧性能和截图/交互证据，不宣称彻底不卡或已完成原 P3–P7。
用户授权本任务在整理后继续实现，并要求与同项目 Astra 对话复核。Astra 的独立审查用于确认路线方向、调度顺序、下钻边界与人群 LOD；实现仍由本任务单写工作区。无须逐阶段批准；遇到需要改变产品方向或破坏旧档的实质障碍才报告。禁止提交、推送、发布和动用户存档。

## 8. 试玩纠偏后的实现边界（R0–R4）

- R0：修复双向道路反向重建、稳定 ETA、逐段检查点、单次最早唤醒和仅校验相关路线。
- R1：补齐暂停/继续/途中折返、段内位置、路线代次和旧 v9 旅行兼容；本地 hex 路径成为持久化分段路线，读档后不依赖 UI 临时数组。
- R2：左键选择、右键前往保持分离；玩家/NPC 路线显示经过点与当前位置；密集人物使用人数聚合、至多 8 个展开标记和溢出数量，名字仅给选中/悬停/关注对象。
- R3：天机城 8 个节点、8 条道路和场所父子关系进入统一 SpatialState；放大或显式“查看内部”进入独立可交互局部地图，城内沿真实道路耗时移动。
- R4：当前只完成天机城这一处稳定局部图；建筑进入后复用既有 Venue 场景，尚未扩展到房间级室内地图。其他聚落没有权威几何时不生成假细节。

## 9. R5–R6：多聚落目录与首个途中相遇

- R5：聚落定义冻结 `definitionVersion`、稳定入口与显示布局；道路物理距离明确为 `distanceMeters`，显示坐标不再冒充米制。静态空间目录升至 v2，只增量补齐缺失节点/道路，不覆盖已封路或归档状态。
- 青云宗拥有独立山门、云阶、外院、青云殿、演武坪与后山断崖拓扑；现有两个 Venue 挂回对应节点。地图 UI 从当前聚落读取视口和 NPC 分组，不再硬编码天机城。
- 聚落加权距离改为 Dijkstra，避免边数更少但物理距离更长的路线被误判为最短路。
- R6：`WorldState.activeEncounters` 与存档 v10 保存未决/进行中相遇；`WorldOutcome.encounterChanges` 让相遇、NPC 行程和事实原子提交。
- 时间推进先求窗口内最早道路接触，只推进到真实接触分钟并返回未执行分钟；未决或进行中的玩家相遇会阻止后续世界推进。交谈/避让恢复双方行程；迎战保留 active 状态，胜负或逃跑后由战斗 outcome 恢复行程并清除相遇。
- 第一版不从事件库抽随机卡，不生成临时妖兽。候选来自真实具名 NPC 的持久化目标/行动/关系与真实 TravelState；更多路边生态、第三方介入和动态绕路留待后续阶段。
- 自动证据：聚落/目录/旅行 20 passed；道路相遇、统一时间、事务与 v1→v10 迁移 51 passed；全仓类型检查通过。
- 隔离 Playwright 正式 UI 复验：青云宗显示 6 个独立节点；玩家与真实具名 NPC 在青云宗—天机城道路中点相遇，日期只推进到第 2 日而非直接抵达；保存内容包含 1 个未决相遇且双方旅行为 paused，加载后相遇卡恢复，选择交谈进入真实 NPC 面板；console/page error 为 0。
- 最终质量门：其余全仓用例已通过；50 年多种子涌现校验对低频传承采用跨世界覆盖与总量门槛，复验得到 4/5 个世界、16 次传承。生产构建和补丁检查通过；浏览器尚未人工打完整场迎战，战斗完成后的原子结算由引擎回归测试覆盖。
