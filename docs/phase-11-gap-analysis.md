# TaoSim 缺陷分析报告

> **基准版本**：Phase 11 完成后（commit fbc1319）
> **分析日期**：2026-08-05
> **对比竞品**：鬼谷八荒 / 论如何建立一个修仙门派 / 了不起的修仙模拟器 / 觅长生
> **定位**：这不是"Bug 清单"，而是"快速发展期遗留的设计空洞"，记录现状以便系统性地补齐。

---

## 背景：为什么会有这些缺陷

TaoSim 从 Phase 1 到 Phase 11，经历了**架构搭建 → 引擎层 → 持久化 → UI 重构 → 可玩性填充**的高速迭代。在 11 个 Phase 内完成了：

- 三层 monorepo 架构（contracts / engine / ui）
- 20+ 引擎模块（修炼/炼丹/锻造/战斗/坊市/NPC/大世界/天劫/词条）
- 完整的创角流程（6 步 + 降临方式）
- 6 面板游戏主界面

**快速发展必然产生代价**：引擎模块虽然各自可用，但模块间的**串联**和**内容填充**严重不足。这是正常的工程规律——先建骨架后填血肉。本报告的目的是把所有"空中楼阁"的部分记录清楚，为后续系统化补齐提供路线图。

---

## 一、核心循环断裂（P0 — 影响可玩性）

这类问题的特征是：**玩家进入游戏后，核心玩法循环跑不通或感受不到反馈**。

### 1.1 修炼循环没有闭环

**现状**：

玩家点"修炼"tab → 点"闭关 12 个月" → 角色年龄增加，修为数字变大。但整个过程是一个黑盒：

- 修为增长公式不可见（不知道灵根/悟性/功法分别影响多少）
- 闭关只有一个 `fastForward(12)` 按钮，没有"本月修为 +XX"的反馈
- 没有"修炼瓶颈"机制（修为够了就能无限涨，没有阻滞感）
- 修炼速度面板不存在

**涉及代码**：
- `apps/taosim-ui/src/game/panels/CultivationPanel.vue` — 只有一个闭关按钮 + 突破按钮
- `apps/taosim-ui/src/composables/useWorld.ts` L43 — `PlayerLifecycleService.advanceTime` 只推进年龄
- 修为增长逻辑散落在 WorldEngine 内部，UI 层完全不可见

**竞品参考**：
- 《觅长生》：修炼有明确的公式展示，玩家能算出闭关收益
- 《鬼谷八荒》：打坐面板显示修炼速度，有瓶颈机制

### 1.2 突破系统只有 3 个配置

**现状**：

`CultivationPanel.vue` 硬编码了 3 个突破配置：

```
炼气9层 → 筑基1层
筑基3层 → 金丹1层
金丹3层 → 元婴1层
```

元婴之后的化神、炼虚、合体等境界**完全无法突破**。且元婴期到化神期的突破配置缺失。

**涉及代码**：
- `apps/taosim-ui/src/game/panels/CultivationPanel.vue` L13-32 — `allConfigs` 数组只有 3 项

**竞品参考**：
- 《觅长生》：10 个大境界完整突破链，每步有独特渡劫设计
- 《鬼谷八荒》：每个大境界突破都有独立的秘境材料需求 + 渡劫战斗

### 1.3 时间推进机制不统一

**现状**：

三个入口各自推进时间，互不关联：

| 入口 | 推进方式 | 副作用 |
|------|---------|--------|
| TopBar "推进 1 月" | WorldEngine.step() + applyPlayerTime(1) | 推进世界 + 角色 |
| TopBar "闭关 1/10 年" | engine.fastForward(12/120) | 推进世界 + 角色，有死亡检查 |
| CultivationPanel "闭关 12 个月" | 调用 world.fastForward(12) | 同上 |
| MapPanel 旅行 | playerStore.advanceTime(days) | 只推进角色年龄，不推进世界 |

旅行消耗的天数只影响角色年龄（`age += days/365`），不影响世界时间（gameYear/gameMonth 不变）。这意味着旅行期间世界是"静止"的。

**涉及代码**：
- `apps/taosim-ui/src/stores/player.ts` L82-87 — `advanceTime` 只改 age
- `apps/taosim-ui/src/game/TopBar.vue` L29-44 — 世界时间推进
- `apps/taosim-ui/src/game/panels/MapPanel.vue` L66 — 旅行调 `advanceTime`

**竞品参考**：
- 《鬼谷八荒》：统一以"月"为最小单位，所有行为（探索/修炼/炼丹）都消耗月数
- 《论建门派》：以"回合"为统一时间单位

### 1.4 战斗系统完全不可玩

**现状**：

虽然底层有完整的 `combat-engine.ts`、`damage-pipeline.ts`、`HexBattlePage.vue`（BattlePage），但：

- NpcPanel 切磋 `playerWin: true` **硬编码**，直接返回胜利结果，不进战斗
- MapPanel 旅行 `battle` 事件只是文字"遭遇妖兽"，无战斗入口
- 没有任何 UI 把玩家引导到战斗页面
- 战斗页面 `BattlePage.vue` 存在但未被任何路由/组件引用

**涉及代码**：
- `apps/taosim-ui/src/game/panels/NpcPanel.vue` L41 — `NPCInteractionEngine.duel(character, npc, true)` 硬编码 true
- `apps/taosim-ui/src/pages/BattlePage.vue` — 孤儿页面，无引用

**竞品参考**：
- 四款竞品全部有完整可玩的战斗系统（实时/回合/自动）
- 战斗是修仙游戏的"风险与收益"核心循环不可或缺的一环

## 二、内容空洞（P1 — 影响体验深度）

这类问题的特征是：**系统能跑，但内容太少/太浅，玩半小时就无事可做**。

### 2.1 奇遇事件极度贫乏

**现状**：

游戏中的事件来源：

| 来源 | 事件类型 | 有选择分支？ |
|------|---------|-------------|
| WorldEngine 月度 Tick | 宏观世界事件（人口/灾劫） | 否 |
| 旅行 OverworldEngine.travel | encounter/battle/material_found/npc_meet | 否 |
| NPC 互动 | 切磋/论道结果文本 | 否 |

**所有事件都是纯文字通知**，没有任何"选择 A / 选择 B"的分支。没有：
- 修炼走火入魔事件
- 偶遇前辈传授功法
- 发现上古遗迹/洞府
- 门派征召令/通缉悬赏
- 与灵根/气运/仙姿属性挂钩的事件触发
- 天材地宝争夺
- 妖兽潮/天灾降临
- 宗门大比/论道大会

**涉及代码**：
- `packages/engine/src/overworld/overworld-engine.ts` L57-86 — 旅行事件只有 4 种，无选择
- `packages/engine/src/world/world-engine.ts` — 月度事件为宏观级

**竞品参考**：
- 《论建门派》：每回合至少 1 个选择分支事件，是核心乐趣来源
- 《鬼谷八荒》：秘境探索有宝箱/陷阱/奇遇NPC/隐藏Boss
- 《觅长生》：大量剧情向奇遇，与灵根/悟道系统联动

### 2.2 秘境探索只是占位

**现状**：

MapPanel 旅行到 Dungeon 节点时：
- 没有任何"进入秘境"的交互
- 没有探索/战斗/奖励
- 没有层数/进度
- 没有危险度提示的实际效果

当前显示的描述：
```
tier <= 2: "灵脉充沛，适宜驻足"
tier <= 3: "灵气浓郁，需谨慎行事"
tier >= 4: "危险区域，机缘与凶险并存"
```

这只是纯展示文字，没有任何游戏机制支撑。

**涉及代码**：
- `apps/taosim-ui/src/game/panels/MapPanel.vue` L116-120 — 纯文字描述

**竞品参考**：
- 《鬼谷八荒》：秘境是多层探索，有 Boss、宝箱、陷阱、隐藏房间
- 《了不起的修仙模拟器》：古代遗迹探索是核心内容

### 2.3 NPC 互动深度不足

**现状**：

NPC 交互面板只有 4 个选项：

| 选项 | 实际效果 | 问题 |
|------|---------|------|
| 切磋 | playerWin 硬编码 true，直接返回胜利 | 没有实际战斗 |
| 论道 | 给固定修为 + 配方概率解锁 | 没有叙事，没有选择 |
| 交易 | 固定商品列表 | NPC 商品无差异化 |
| 离开 | 清空 currentNPC | — |

缺失的社交系统：
- 没有拜师/收徒（CharacterRelation 有 Master/Disciple tag 但无功能）
- 没有道侣/结义（有 TaoistPartner tag 但无功能）
- 没有送礼功能
- 没有仇敌系统（有 Enemy tag 但 NPC 不会主动攻击）
- NPC 之间没有自主互动
- NPC 没有性格系统（慷慨/阴险/高傲等）
- NPC 不会自行成长（境界提升）

**涉及代码**：
- `apps/taosim-ui/src/game/panels/NpcPanel.vue` — 只有 4 个交互
- `packages/contracts/src/character.ts` L57-64 — CharacterRelation 有 tags 但无消费者
- `packages/engine/src/interaction/npc-interaction-engine.ts` — 只有 duel/discuss/getPriceMultiplier

**竞品参考**：
- 《鬼谷八荒》：NPC 有完整性格系统，道侣双修加成，师徒传授功法，NPC 间自主恩怨
- 《觅长生》：道侣双修加成，师徒学习独门功法
- 《论建门派》：弟子间产生情愫/恩怨，有忠诚度/叛逃机制

### 2.4 配方和材料内容过少

**现状**：

| 类别 | 数量 | 问题 |
|------|------|------|
| 丹方 | 3 个（聚气丹/筑基丹/延寿丹） | 太少 |
| 锻造配方 | 3 个（灵蕴剑/灵甲/星辰剑） | 太少 |
| 材料种类 | 5 tier × 2-3 种 = ~12 种 | 来源单一（仅旅行） |
| 材料来源 | 只有旅行 material_found 事件 | 无种植/采矿/购买 |

**涉及代码**：
- `packages/engine/src/crafting/recipe-registry.ts` — 6 个配方硬编码
- `packages/engine/src/overworld/overworld-engine.ts` L19-25 — MATERIAL_POOL

**竞品参考**：
- 《了不起的修仙模拟器》：数十种丹方，材料有完整生产链（种植→加工→炼制）
- 《觅长生》：丹药是核心经济循环，配方和品级丰富

### 2.5 功法学习系统完全缺失

**现状**：

角色初始有 0-1 个技能（取决于家世），之后**完全没有途径学习新功法**：

- 没有功法书/秘籍物品
- 没有宗门功法学习
- 没有 NPC 传授功法
- 没有秘境掉落功法
- 没有自创/参悟功法
- `Skill` 系统有 AtomicNode primitives 设计（程序化合成），但没有入口

CharacterDetailModal 的"功法技能"区永远只有 0-1 条。

**竞品参考**：
- 四款竞品全部有丰富的功法获取途径
- 《觅长生》功法品级（黄/玄/地/天）+ 悟道永久增益是核心成长线
- 《鬼谷八荒》功法意境系统 + 参悟/熟练度

## 三、系统空壳（P2 — 有数据模型无功能）

这类问题的特征是：**数据结构和引擎代码存在，但没有 UI 入口或功能未激活**。

### 3.1 宗门系统空壳

**现状**：

Character 有 `factionId` 和 `factionRank` 字段，`faction-engine.ts` 存在，但：

- 无法主动加入/退出宗门（只在创角时按家世自动赋予）
- 无法在宗门内晋升
- 宗门不提供任何功能（学习功法/接任务/获取资源）
- 没有宗门 UI 入口
- `FactionRank` 枚举（Disciple/Deacon/Elder/Leader）无消费者

**涉及代码**：
- `packages/contracts/src/character.ts` L126-127 — factionId/factionRank 字段
- `packages/engine/src/faction/faction-engine.ts` — 引擎存在但无 UI

**竞品参考**：
- 《鬼谷八荒》：外门→内门→长老晋升，宗门任务/贡献点/专属功法
- 《觅长生》：宗门是功法获取的主要途径

### 3.2 拍卖行缺失

**现状**：

MarketPanel 是固定商品列表，没有拍卖机制。`market-pricing.ts` 和 `market-transaction.ts` 只支持固定价格买卖。

**涉及代码**：
- `apps/taosim-ui/src/game/panels/MarketPanel.vue` — 固定商品
- 无拍卖行相关代码

**竞品参考**：
- 《觅长生》《鬼谷八荒》都有定期拍卖会，是高价物品核心途径和社交场所

### 3.3 悟道/修炼方向系统缺失

**现状**：

角色修炼只是修为数字线性增长，没有任何方向选择。`SpiritElementType`（金木水火土+变异）定义了灵根元素，但没有：
- 元素方向的修炼增益
- 五行相克在战斗中的体现
- 修炼路线选择（剑修/法修/体修）

**涉及代码**：
- `packages/contracts/src/character.ts` L27-29 — SpiritElementType 定义存在
- `packages/engine/src/combat/damage-pipeline.ts` — 无五行相克计算

**竞品参考**：
- 《觅长生》悟道系统（五行/剑道/体修方向的永久增益）是核心策略深度
- 《鬼谷八荒》功法意境系统（剑意/拳意等）

### 3.4 存档/读档功能未接入 UI

**现状**：

`app.ts` store 有完整的 `saveGame` / `loadGame` / `deleteSave` 实现，IndexedDB 持久化层完整。但：
- 游戏内没有"保存"按钮
- 没有"读取存档"界面
- 铁人模式的月度自动存档在 useWorld.ts 中有代码，但无 UI 反馈

**涉及代码**：
- `apps/taosim-ui/src/stores/app.ts` L49-90 — saveGame/loadGame 完整实现
- 无任何 UI 调用这些方法（除了 useWorld.ts L63 的铁人自动存档）

## 四、数值与平衡（P2 — 影响体验质量）

### 4.1 修炼速度完全不可见

闭关 1 年后修为涨了多少？灵根品级影响多少？悟性 10 vs 20 差多少？**玩家完全无法判断**，闭关变成盲操作。

### 4.2 灵石经济失衡

| 开局 | 灵石 | 问题 |
|------|------|------|
| 诞生 ancient-clan | 2000 | 可直接买空坊市，无经济压力 |
| 穿越 白板 | 0 | 材料来源全靠旅行偶遇，初期卡死 |
| 诞生 orphan | 100 | 基本够用但偏少 |

坊市商品价格没有与节点 tier 联动，灵石缺乏持续消耗的刚需项。

### 4.3 旅行事件概率固定

旅行事件触发率 `0.3 + luck/200`，与节点类型/区域危险度无关。荒野和城镇的遭遇概率一样，不合理。

## 五、沉浸感缺失（P3 — 影响长期留存）

### 5.1 诞生模式的童年体验缺失

选择诞生 → age 直接设为 6 → 没有任何童年事件。降生故事文本只是创角时看一眼，进入游戏后再也看不到了。没有成长过程的事件链。

### 5.2 世界感缺失

- 地图只有 12 个节点，且没有视觉地图（只是文字列表）
- 看不到其他 NPC 在哪里活动
- 世界没有任何动态变化（势力消长、天灾降临、秘境开启）
- EventLog 只显示宏观世界事件，不显示角色相关事件

### 5.3 角色死亡后的处理单薄

角色寿元耗尽 → 直接进入 GameOverScreen → 显示墓志铭 → 结束。没有传承/转世/后人继承机制。`SoulState`（PrimordialSoul/RemnantSoul）有定义但无功能。

**竞品参考**：
- 《论建门派》"掌门传承"机制：角色死亡后由弟子接班继续经营
- 《了不起的修仙模拟器》：门派不会因单个角色死亡而结束

## 六、技术债务（P3 — 不影响当前功能）

### 6.1 OverworldPage 孤儿页面

`apps/taosim-ui/src/pages/OverworldPage.vue` 有完整的大地图旅行逻辑，但未被任何路由引用。MapPanel 重写后，OverworldPage 的逻辑已被吸收，可考虑删除。

### 6.2 BattlePage 孤儿页面

`apps/taosim-ui/src/pages/BattlePage.vue` 存在但未被引用。战斗系统接入后需要决定是复用还是重写。

### 6.3 部分引擎模块有完整测试但无 UI 消费者

`faction-engine.ts`、`market-pricing.ts`、`npc-ai.ts` 等模块有完整实现和测试，但没有 UI 入口调用它们。

## 八、TaoSim 的独特优势（不要丢失）

在补缺陷的同时，以下差异化优势需要保持和强化：

1. **ATB 战棋系统**：`damage-pipeline.ts` + `combat-engine.ts` + Hex 六边形地图的 ATB 回合战棋，是市面上修仙游戏都没有的独特定位
2. **程序化功法合成**：`Skill` 的 AtomicNode primitives 设计（几何/数值/效果原子组合）允许程序化生成功法，潜力远超固定功法列表
3. **双层世界架构**：WorldEngine（宏观世界 Tick）+ OverworldEngine（微观角色旅行）的双层设计，为后续"活世界"留足了扩展空间
4. **CharacterRelation 多维关系**：favorability/hatred/jealousy + tags 的设计比多数竞品的关系模型更丰富
5. **降临方式系统**：诞生（家世 + 降生故事）vs 穿越（白板 + 悟性加成）的双模式创角，在竞品中少见
