## 1. 本轮要交付什么

交付一个无 AI 也能游玩的修仙生活版本：玩家进入已有历史的世界，能看懂附近的人与机会，自主选择获取资源、学习成长和处理冲突的办法；NPC 同期行动；结果能跨界面、离开、快进和读档持续存在。

本轮用一个聚落及其周边形成完整体验，复用既有世界规模与目录，不删减旧世界。首次验收以 3–5 个有效地点、约 10–20 名关键人物为建议范围；其他人口照常存在。规模是可调原型参数，不是必须新建一套人物系统的要求。

- 保留 [统一世界蓝图](systemic-cultivation-world-blueprint.md) 的实体身份、场景投影、事务和存档边界。
- 复用 [NPC 大脑方案](npc-brain-and-combat-architecture.md) 的局部认知、计划、真实具名战斗和 AI 提案边界。
- 复用 [动态空间方案](dynamic-spatial-world-implementation-plan.md) 已建设的包含树、连接图、动态差量与时间调度，不重复建设第二套底座。
- 旧文档“已完成”仅视为历史报告；正式玩家路径是否成立，以本轮复现和验收为准。
- 仇敌调查与战斗放进本地生活冲突；秘境现世保留并回归检查，本轮不继续增加秘境种类。
- 范围外：完整生态/天气、跨界扩容、新种族体系、渡劫/夺舍/兽潮重做、完整宗门经营、无限功法生成、线上多人和商业 AI 服务部署。

### 1.2 完成的定义

工程通过、规则成立、玩家能看懂、玩家愿意继续，分别报告。测试通过不等于好玩；不得宣称量化达到“95%好玩”。P7 需给出实际可操作的试玩路线、选择差异及未解决体验问题。

## 3. 产品规则

### 3.1 真实性与自由度

真实性验收：连续性、因果性、自主性、一致性、可理解性和可干预性。
自由度验收：同一目标存在不同成本、风险、关系后果的可行办法；失败后仍有适应和继续的空间。
新增细节必须改变至少一种行动判断；纯粹要求玩家重复维护的负担先不加入。

### 3.2 世界初始化与三种入口

生成成熟的初始社会结构，再运行可复现前史，最后接入玩家。初始设定与模拟产生的历史标注来源，不伪造“实际发生过”的因果。无需从第一个生命开始推演。

- 穿越：选定世界时点后创建/接入角色，有明确年龄、身份、资产来源和所在地点。
- 降生：角色出生在实际家庭/环境；提供最小关键童年选择及阶段快进，家庭与周边世界同期发展。不得把“降生”仅做成六岁角色的改名按钮。
- 上帝：同一世界规则，允许全知观察与明确的有限干预工具；干预写入可追踪原因。首版提供暂停/倍率、追踪人物和至少一种有边界的干预（例如有来源标记的资源补给），不伪装角色正常获取。
- 世界日期、角色年龄、现实游玩时长独立。角色与上帝的知识视图分开；角色视图不泄漏完整 NPC 计划评分与秘密。

### 3.3 时间与行动

复用 elapsedMinutes 和已有调度。行动具有开始、预计完成、目标、成本、状态和中断结果。实时是推进源，行动完成按时间表结算；禁止实时计时后再次追加整段行动耗时。
默认节奏验证“慢速实时＋主动暂停＋行动快进”。暂停必须清楚显示；可以配置首次进入暂处暂停状态，避免开局阅读时被迫流逝。倍率与每步时间是配置，不先承诺唯一最佳值。

快进遇到需要玩家选择的事件停下；按关键时间点结算到达、资源争夺、伤势、期限和战斗，不按大步长跳过中间事实。读档、切面板和改变观测不能重复完成行动。
游戏内阅读不产生额外行动成本。无效操作不扣费；有效行动执行后失败可以按明确规则消耗。生活成本以时间/资源表达，战斗 AP 可以保留其战术意义。

### 3.4 空间与地图

地理尺度负责势力和远行；区域负责路线、风险、资源与人物活动；现场负责交互与战斗。保持包含树和连接图，不要求新增固定地图枚举。
位置只有一个权威来源。地图标记、路线插值、旧 currentNodeId/hexPos 均是兼容或展示投影；挂载 UI 不得把人物传回地标。
重要资源点、危险源和现场具有身份、数量/状态、所有者（如适用）与生命周期。移动遭遇按实际时空接触或发现条件发生，不能因分辨率更细而增加每公里危险次数。

### 3.5 NPC、经济与成长

复用现有大脑、记忆和行动提交，避免新旧选择器同时正常执行同一人的行动。计划绑定具体地点、物品、人物和期限；信息可以过期，行动可以被拒绝、阻断或抢先。
关键资源使用共享来源、库存和转移记录；人物死亡/离场不得复制物品。普通物资可聚合。报价和成交使用同一计算入口，税费/议价在提交前展示；刷新和读档不创造库存。

成长要提供能力变化：首版至少有可学习的基础功法、可完成的材料获取与炼制、基于实际学习差异和时间的交流。反复讨论已掌握内容不能成为无限无成本收益。
最小关系包含记得共同经历、履约/违约及帮助/伤害后果，优先复用现有语义；不新增孤立好感进度条。初期失败可以是损失、伤势、误期或关系变化。

### 3.6 事件与文字

区分“世界现象/行动”“发生的事实”“角色发现的信息”“需要决定的交互”。事件模板只负责条件、规则配方和表达。
重要事件实例需能确定：来源/原因、地点、参与者、当前状态、开始/截止/恢复条件、结果与后续关联；字段可映射已有结构，不要求另建平行事件总线。
清理危险会影响当地后续风险，采集会减少库存并等待恢复，求助会解决/过期/被别人处理。角色离开不将事件重置。
普通风景允许随机表达，但不能凭空创造具名人物、可售资源、战斗结果和已解决问题。随机源支持存档和回放；不要仅靠降低概率或改文案验收。

即时反馈简短显示；个人记事记录承诺、线索、关系和目标；人物/世界历史按需查询。例行修炼、重复路过与零收益合并，玩家可以查真实明细。重要消息只对知道或可感知的角色开放。

### 3.7 战斗

保留现有新 BattleEngine 作为正式结算方向，具名 NPC 同规则。先做战前准备—现场战斗—逃跑/投降—伤势/资产/关系回写。
首版至少让两种可获得手段与防御/撤退存在不同适用局面，验证距离、消耗、准备或地形能改变选择。修复无效技能/自身目标选择；不以技能数量验收。
场景从遭遇地点投影地形、入口和参与者，禁止每次打开无关随机战场。思考可暂停；执行耗时与世界时间对齐。战斗中参与者不能同时在世界另一处交易/修炼；关键第三方到达必须明确处理，首版可先支持加入候选或在行动边界中断，不能静默丢弃。
终局一次性提交全部受影响实体，包含伤势、资产、关系与事实；重复回调/读档不能重复奖励。未完成战斗的保存边界必须明确，优先支持可恢复快照，若技术上暂不支持则在 UI 明示并列为未达验收，不许静默丢进度。

### 3.8 AI 与扩展

本轮交付结构化提案边界与无网络测试，不默认接入付费服务。协议覆盖对话上下文、玩家意图、重要 NPC 计划和受约束内容创意；实现至少“请人代送药材”的自由请求到合法配送行动的适配测试。
AI 只能看到角色已知事实，输出需校验能力、在场、资产、成本、期限和权限；执行前重新验证当前世界版本。拒绝/超时/过期回复均不修改世界。规则大脑保持可用。外部文字不能成为系统指令或直接执行代码。
AI 模板或模拟提供器只用于测试，正式 UI 不把模板冒充联网智能。已有真实服务门面保留，但真实联网接入、密钥和费用待独立授权。
新增内容通过已有注册表和规则组件接入；本轮不建设万能脚本语言或无边界模组平台。

## 4. 统一试玩场景

复用一个现有聚落及周边，具体地点与角色由 P0 依资源适配选择，记录固定种子。目标是“获得基础功法并完成一炉有用的丹药”，可继续发展到治疗、交付或突破准备。

世界设定包括实际药材点、药商库存、采集者、需求者和一条有风险的路线。供给压力由库存、采集进度、道路和人物计划形成；不得按玩家脚本步骤强制制造短缺。

可行办法至少三种：合法交易/交换、亲自采集、帮助或委托他人。冲突分支包括调查风险、护送、抢夺或绕行中的可实现组合，至少贯通一种具名冲突。主流程不强制杀人、固定人物获胜或按指定顺序完成。

所有办法共用资源、旅行、制造与事实。至少比较玩家不参与、正常帮助、提前抢先/改道三种运行；结果可以收敛，不要求每个种子戏剧性分叉，但选定验收夹具中应有可解释的不同结果。

## 5. 架构职责与决策

六个边界：时间调度；空间环境；人物组织与认知；行动结算；事实存档；感知表现与 AI 提案。复用现有 contracts/engine/persistence/UI，不创建平行存储或另一套全局时钟。

| 决策 | 选择与原因 | 代价与恢复方式 |
|---|---|---|
| D1 一次统一的生活切片 | 优先日常资源—成长—冲突，再扩大秘境 | 暂缓外围功能；旧秘境保留回归，不删除 |
| D2 同一事实、多种视角 | 角色有限信息，上帝全知 | 投影要显式过滤；可以回退展示，不能改世界结果 |
| D3 实时与快进共用调度 | 行动持续存在，避免重复耗时 | 迁移旧即时按钮；适配器短期保留但只允许一条写入口 |
| D4 持续事件代替每步抽卡主流程 | 保留随机条件和环境描述 | 初期事件数较少；通过有效行为组合扩充，不能退回造假事实 |
| D5 局部精细、远方按关键时间结算 | 身份/资产/行动/结果一致，关闭渲染可节省开销 | 性能按基准校准；不得用观测改变胜负 |
| D6 有界 AI 提案 | 对话、意图和计划可扩展，权威结算稳定 | 自由输入有能力边界；失败回落规则系统 |

## 6. 领域风险与硬约束

| 维度 | 风险 | 必须保证 |
|---|---|---|
| 不变量 | 人物瞬移、资源复制、时间倒退 | 身份/位置/资产/时间/已发生事实只有权威来源 |
| 原子性 | 扣钱未交货、战斗只回写玩家、先扣 AP 后判断无效 | 先验证再提交；跨实体结果全成或全败；有效执行失败明确损耗 |
| 并发 | NPC 和玩家买最后一份、实时与快进同时推进、重复回调 | 同序调度、资产预留或提交校验、幂等行动 ID；时钟串行推进 |
| 副作用 | 奖励重复、用户存档损坏、迁移部分成功 | 测试副本、旧存档保留；迁移成功后再替换；历史和奖励去重 |
| 信任边界 | AI 全知/造物、UI 绕过规则 | 受限认知输入、结构校验、权限与世界状态重验 |
| 可观测性 | 只见弹窗无法追原因，错误吞掉 | 行动 ID、前后时间、实体、原因、结果、失败点可追查；玩家日志独立于诊断日志 |
| 性能 | 全量复制/逐帧所有大脑/无界历史 | 测量主线程、队列、存档；索引与关键时间推进；保持人口/活动与历史有界策略 |

存档迁移覆盖仓库实际支持的全部旧版本。历史讨论提到 v5–v9，P0 先核对真实迁移表；不存在真实旧档时使用明确标注的版本夹具，不能宣称已验证用户旧存档。快进一致性以固定种子、相同行动输入及稳定事件排序比较领域结果；浮点误差和展示插值容差单独定义。

## 7. 分阶段实施与退出门

每个阶段先核对现有实现，记录采用/修复/补齐，不以新建文件数量作进度。以下输入、输出与回退边界是实施分解；Sol 在 P0 补充最短具体文件映射，不另写重复大蓝图。

| 阶段 | 输入与工作单元 | 交付与退出门 | 风险/回退 |
|---|---|---|---|
