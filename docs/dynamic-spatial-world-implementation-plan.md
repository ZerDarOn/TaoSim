## 0. 决策摘要

TaoSim 当前缺少的不是更大的六边形地图，而是一套能同时回答以下问题的权威空间系统：

- 世界里真实存在什么地方；
- 人物此刻在哪里、为什么在那里、正在去哪里；
- 距离、速度和时间怎样共同决定移动；
- 秘境、空间裂缝、结界和灾害怎样真实改变空间；
- 地图变化怎样影响 NPC 的认知、计划、战斗、经济和势力；
- 玩家怎样在不看像素小人的情况下持续观察这一切；
- 快进与正常流逝怎样得到相同的世界结果。

本方案冻结以下决策：

1. 地图从“玩家旅行操作器”升级为“权威世界的观察与交互投影”。
2. 世界空间由三套正交结构组成：**包含树、连接图、动态覆盖层**。
3. 不继续把所有空间概念塞入固定 `MapLayer` 枚举；领域空间允许可嵌套节点，UI 使用少量语义缩放层。
4. 在 Region 与具体地点之间增加关键尺度 **LocalArea**，承载道路、山谷、城郊、森林、NPC 连续移动和局部遭遇。
5. 秘境不是固定的“第八层”，而是通过入口连接到主世界的独立口袋空间；小秘境可以只有场景，大秘境可以拥有自己的区域层级。
6. 空间裂缝、结界、灾害区、灵潮和势力边界是有生命周期的动态空间特征，不是日志文本或静态图标。
7. 基础地图保持稳定，世界变化以稀疏差量和事实历史持久化，不在每次变化时重写整张地图。
8. 事件库只保存触发规则、条件、结算配方和表现模板；实际事件必须由状态、人物意图和规则结算产生。
9. 玩家与 NPC 的移动统一为“路线、距离、速度、开始时间、预计到达时间”；位置不再按月随机跳转。
10. 世界只使用一个权威时钟；普通流逝、行动耗时、旅行、闭关和快进只是不同的推进请求。
11. 所有具名 NPC 都使用不依赖 LLM 的规则大脑；模拟精度可以降低，但人物身份、计划、伤势、资产和事实不能丢失。
12. 具名 NPC 战斗统一进入真实战斗解析器；是否被玩家观看只改变表现精度，不改变胜负规则。
13. AI 只负责重要人物的反思、自由意图、计划提案、对话和叙事，不直接创建地图事实或宣布事件成功。
14. 地图 UI 保持中心舞台，选中 NPC 后地图不消失；当前行动、理由、路径、预计到达和事实时间线在同一观察上下文中呈现。
15. 实施采用阶段质量门；不按文件频繁跑全量测试，也不把全部重构压成一个不可回滚提交。

## 1. 现状复盘

### 1.1 已有基础

当前项目已经具备可复用的部分：

- 星界、大陆、区域、聚落和场所的初步目录；
- 六边形地形、寻路和玩家移动原型；
- 天机城聚落节点和道路；
- 权威绝对时间 `elapsedMinutes`；
- NPC 稳定档案、大脑、记忆、目标、计划与节点观察器；
- 世界事实、事件日志、传闻和编年史雏形；
- 具名 NPC 战斗和世界差量提交方向；
- 玩家关注列表和模拟精度分层的初步概念。

这些基础应迁移、适配和收敛，不应无差别推倒重写。

### 1.2 当前关键断点

1. [`MapLayer`](../packages/contracts/src/multi-layer-map.ts) 是固定展示枚举，却被同时当作领域空间层级。
2. [`LocationRef`](../packages/contracts/src/location.ts) 只有大陆、节点、场所和六边形位置，无法稳定表达 LocalArea、场景、途中位置、口袋世界和空间层。
3. [`WorldState`](../packages/contracts/src/world-state.ts) 只有节点灵气和人口格，没有动态空间实体、连接变更和地图差量账本。
4. [`HexOverworldEngine`](../packages/engine/src/overworld/hex-overworld-engine.ts) 把固定 20×20 网格同时当作大陆展示、局部探索、移动距离和事件触发器。
5. [`WorldEngine`](../packages/engine/src/world/world-engine.ts) 的 NPC 位置主要按月维护；无 `locationId` 的人物还可能随机重新落脚，无法表现连续活动。
6. [`npc-spatial`](../packages/engine/src/overworld/npc-spatial.ts) 的云游近似为每月一格，与真实距离、人物速度和行动计划脱节。
7. 旧节点旅行、六边形旅行、聚落道路和战斗场景分别计算空间，没有唯一距离与路线来源。
8. [`calendar-event-scheduler`](../packages/engine/src/time/calendar-event-scheduler.ts) 中的“秘境开启”“天灾临世”主要是概率定义和描述，未生成可进入、可持续、可消失的地图对象。
9. UI 选中 NPC 后切走地图，日志长期占据窄侧栏，玩家无法同时观察空间、人物行动和因果。
10. 普通移动、出生和例行行为容易淹没日志；地图又没有足够的即时状态表达，导致“世界不动，日志在演戏”。

### 1.3 根因

当前地图混合了四种不同职责：

- 权威世界空间；
- 玩家已知地图；
- 旅行输入界面；
- 视觉渲染快照。

只改地图尺寸、标记密度或动画不能解决问题。必须先建立唯一权威空间，再让移动、NPC、事件和 UI 都从它投影。

## 2. 产品目标与非目标

### 2.1 产品目标

关闭 AI 后，玩家仍应能观察到：

- NPC 从住处前往工作、修炼、交易、拜访、调查、追踪和伏击；
- 两个 NPC 因时间和路线重合而相遇，也可能因为改道而错过；
- 地点有所有者、在场者、资源、危险、法律、历史和当前状态；
- 秘境出现后，附近人物和势力根据信息、性格和利益做出不同反应；
- 道路被毁、结界升起或裂缝扩张后，路线、价格、迁徙和冲突发生连锁变化；
- 玩家离开一个地方后，那里仍按照相同世界时间继续变化；
- 玩家选中任何重要人物，都能解释“为何想到、为何选择、正在做什么、何时变化、结果如何”。

接入 AI 后增加：

- NPC 对既有事实的自由表达和对话；
- 重要人物基于个人认知提出非模板目标与复杂计划；
- 功法、阵法、秘境规则和行动创意的结构化提案；
- 对战斗、灾害和历史事实的丰富描述。

### 2.2 非目标

- 不复制 WorldBox 的像素视觉；
- 不逐帧模拟全世界所有人口；
- 不让 1500 个具名 NPC 每分钟完整扫描全部大脑节点；
- 不把每个建筑、房间和树木永久实例化；
- 不允许随机事件模板直接制造人物胜负、物品归属或历史；
- 不让普通术法默认永久改变大陆地形；
- 不在首轮同时建设完整天气、生态、海洋、地下世界和跨界飞升内容；
- 不为短期演示在正式路径中生成临时 NPC、假秘境或无法回写的地图标记。

## 3. 统一概念

### 3.1 空间包含树

表示“某个地方属于哪里”：

```text
界域 Plane
└── 星域/世界 Cosmos
    └── 大陆 Continent
        └── 地域 Region
            └── 地方 LocalArea
                └── 地点 Site
                    └── 场所 Venue
                        └── 场景 Scene
```

不是每个分支都必须经过全部层级。例如荒野山洞可以从 LocalArea 直接进入 Venue；大型宗门可以在 Site 下拥有多个子区域和场所。

### 3.2 空间连接图

表示“怎样从一个地方到另一个地方”：

- 道路、河道、山口和城门；
- 传送阵、遁界通道和空间裂缝；
- 秘境入口与出口；
- 单向入口、境界门槛、身份权限和时间窗口；
- 临时封路、桥梁损毁、结界阻断。

包含关系不等于可达关系。两个地点同属一片区域，也可能因为结界、地形或战争暂时无法互通。

### 3.3 动态覆盖层

表示“空间现在受到什么影响”：

- 地形和通行；
- 灵气、资源和生态压力；
- 危险、毒雾、火灾、洪水和兽潮；
- 结界、禁飞、压制、感知屏蔽和阵法；
- 势力控制、法律和战争前线；
- 玩家/NPC 的已知、传闻、误认和未知。

### 3.4 事件术语分离

后续禁止继续把以下概念统称为 Event：

```text
Pressure   世界压力：灵脉失衡、资源短缺、仇恨、灾害条件
Trigger    唤醒条件：达到阈值、时间到期、人物进入范围
Intent     人物/势力打算做什么
Resolution 规则验证和结算
Outcome    待原子提交的世界差量
Fact       提交成功后已经发生的事实
Narrative  模板或 AI 对事实的语言表达
```

事件库保留的是 Trigger、Resolution 配方和 Narrative 模板，不是预写的历史结果。

## 4. 目标架构

```text
WorldClock + TemporalScheduler
             │
             ▼
   Pressure / Intent / Lifecycle
             │
             ▼
      Spatial Resolution
             │
             ▼
          WorldOutcome
             │ 原子提交
             ▼
┌─────────────────────────────────────┐
│ 权威世界                            │
│ SpatialNodes / Links / Features     │
│ NPC / Assets / Factions / Conditions│
│ FactLedger / WorldRevision          │
└─────────────────────────────────────┘
        │                 │
        ▼                 ▼
 Perception/Knowledge   RenderProjection
        │                 │
        ▼                 ▼
 NPC 大脑 / AI 提案      地图 / 日志 / 编年史
```

建议划分六个模块：

1. **Spatial Model**：空间节点、包含关系、连接、地址、坐标、尺度和静态目录。
2. **Spatial Runtime**：动态特征、地图差量、生命周期、可达性、空间索引和路径失效。
3. **Temporal Simulation**：唯一时钟、优先队列、分层唤醒、旅行进度和快进。
4. **Intent & World Outcome**：移动、探索、封印、开启、破坏、进入和逃离的验证与原子提交。
5. **Perception & Projection**：NPC/玩家认知、传闻范围、关注对象、地图聚合和事实查询。
6. **Observation UI**：语义缩放、NPC 观察、动态图层、地图变化、日志和快进反馈。

构建顺序固定为 1 → 2 → 3 → 4 → 5 → 6；允许准备并行，但正式接线不能逆序。

## 5. 权威空间模型

### 5.1 空间节点

每个空间节点至少拥有：

- 稳定 ID、名称和种类；
- 父空间 ID；
- 自己的坐标系和物理尺度；
- 边界或锚点；
- 默认地形、灵气、危险和管辖；
- 是否可以包含子空间；
- 当前存在状态；
- 创建、改变或毁灭的事实引用。

空间种类描述语义，不强迫固定深度：Plane、Cosmos、Continent、Region、LocalArea、Settlement、Sect、Wilderness、Ruin、ResourceSite、Venue、Interior、Scene、PocketRealm 等可以共享同一个通用节点协议。

### 5.2 空间地址

权威位置不再由多个互相猜测的可选字段组成，而是至少包含：

- 所在空间节点；
- 节点内坐标或锚点；
- 所在空间层/高度层；
- 当前状态：静止、途中、场景中；
- 必要时携带完整祖先路径缓存，但祖先路径可从空间树重建。

玩家与 NPC 使用同一位置语义，但仍可由不同权威档案持有。

### 5.3 连续旅行状态

旅行必须保存：

- 出发位置和目标位置；
- 已验证路线和所用连接；
- 总距离与剩余距离；
- 移动方式、队伍和速度快照；
- 开始时间、预计到达时间和下一空间检查点；
- 可中断原因和已发生遭遇；
- 路线所依据的地图修订号。

地图渲染可以按时间插值人物位置，但插值只是表现。权威状态以路线进度和世界时间为准。

### 5.4 物理尺度

每个坐标系必须声明单位或尺度。格子不能直接等于一天：

```text
路径距离 = 所有路线分段的物理距离之和

有效速度 = 基础速度
         × 移动方式
         × 境界与功法
         × 地形与道路
         × 天气与结界
         × 伤势与负重
         × 队伍限制

旅行时间 = 路径距离 ÷ 有效速度
```

传送同样具有准备、排队、启动和冷却时间，不能绕过世界时钟。

### 5.5 口袋空间与秘境

秘境采用独立空间域：

- 主世界保存入口锚点；
- 入口通过 PortalLink 指向秘境根节点；
- 秘境拥有独立子空间、规则、生态、资源和时间倍率；
- 开启窗口、权限、稳定度和崩塌时间属于入口或秘境特征；
- 入口关闭不等于秘境数据删除；永久坍塌后才进入历史归档；
- 关闭前必须结算仍在内部的人物：离开、被困、传送、失联或死亡，禁止静默移动。

小秘境可以延迟生成内部细节，直到有人进入；生成种子和已发生事实必须持久化，保证再次进入一致。

## 6. 动态空间与地图变化

### 6.1 基础地图与世界差量

地图分两层保存：

1. **BaseMapDefinition**：世界种子、静态大陆轮廓、基础区域、永久地标和默认道路。
2. **DynamicSpatialState**：新增/关闭空间、连接变化、地形差量、动态特征、所有权和生命周期。

加载时由基础地图叠加当前有效差量生成权威空间快照。渲染缓存、聚合热力图和动画轨迹不进入存档。

### 6.2 动态空间特征

统一特征至少覆盖：

| 特征 | 核心状态 | 典型影响 |
|---|---|---|
| 秘境入口 | 潜伏/征兆/开启/不稳/关闭/坍塌 | 新空间连接、资源、争夺、困人 |
| 空间裂缝 | 强度、方向、目标、扩张范围 | 传送、怪物涌入、空间伤害、改道 |
| 结界/阵法 | 边界、权限、耐久、供能、规则 | 阻挡移动/感知/飞行、保护或囚禁 |
| 灾害区 | 范围、强度、速度、结束条件 | 地形、人口、资源、迁徙、伤亡 |
| 灵脉/灵潮 | 范围、属性、浓度、稳定度 | 修炼、资源、妖兽、势力竞争 |
| 战争前线 | 双方、控制度、补给、危险 | 路线、法律、市场、战斗和难民 |

每个特征必须记录创建原因、作用范围、生效时间、下一转变时间、可见性、规则效果和结束事实。

### 6.3 生命周期

统一生命周期：

```text
latent → omen → active → stable/expanding/contested
       → weakening/sealed/collapsing → closed/ruined/archived
```

不同特征可以裁剪阶段，但不得只保存“存在/不存在”。生命周期的下一转变时间进入时间调度器，不需要每分钟扫描全部特征。

### 6.4 地图变更操作

地图差量支持有限且可验证的操作：

- 创建、启用、禁用或归档空间节点；
- 创建、关闭、改变连接及通行条件；
- 修改局部地形、危险、灵气、资源和管辖；
- 对区域做临时或永久覆盖；
- 拆分/合并空间只能作为高等级迁移操作，首版不开放给普通事件。

每次变更注明：范围、持续时间、原因事实、前置地图修订号、受影响实体和补偿措施。

### 6.5 战斗对世界地形的影响

战斗地图变化和世界地图变化必须分级：

- 普通技能：只影响当前战斗场景或短时间环境；
- 高强度技能/阵法：可升级为 Venue 或 LocalArea 差量；
- 大能交战/天灾：经过专门世界结算才可升级为 Region 影响；
- 任何持久变化都由 WorldOutcome 提交，战斗原子不能直接改大世界状态。

这样既允许“化神一击斩断山峰”，又避免每次火球术永久烧毁大陆。

## 7. 因果事件链

### 7.1 通用链路

```text
世界状态/人物行为产生压力
→ 触发器唤醒相关规则或大脑
→ 形成空间或行动意图
→ 校验时间、位置、资源、权限和目标
→ 规则解析实际结果
→ 原子提交人物、地图、资产、势力和时间差量
→ 提交成功后生成事实
→ 参与者感知、形成信念/记忆/传闻
→ 模板或 AI 生成叙事
```

### 7.2 秘境现世示例

1. 地图生成时已有潜伏古阵种子，或后续因灵潮与地脉变化形成条件。
2. 稳定度跌破阈值后进入“征兆”，附近出现灵气异常事实。
3. 能观察到征兆的人物形成调查、汇报、隐瞒或抢占意图。
4. 到达开启时间后创建入口连接，并按种子生成最小秘境结构。
5. NPC 根据个人认知、风险偏好、关系和宗门职责决定前往、封锁、出售情报或避开。
6. 争夺、交易、伏击和战斗由真实人物与真实资产参与。
7. 稳定度耗尽时进入崩塌，正在内部的人物收到逃离目标。
8. 关闭后入口失效，幸存、失踪、死亡、遗留资源和地形伤痕进入事实历史。

### 7.3 空间裂缝示例

裂缝产生后必须真实改变：连接、附近危险、灵气属性、NPC 路线、妖兽来源和势力行动。若裂缝只是地图图标与一条日志，则不算实现完成。

### 7.4 天灾示例

天灾应先确定真实作用范围和强度，再计算：

- 道路、建筑和地形损坏；
- 在场人口与具名人物的逃亡、受伤和死亡；
- 资源与市场变化；
- 势力救援、封锁和争夺；
- 灾后灵脉、遗迹和迁徙。

“天灾临世”不得只增加乱世指数并输出描述。

## 8. 时间、NPC 调度与快进

### 8.1 唯一时间入口

所有系统读取同一个绝对时间。任何行动只能提交耗时，不能私自修改年月日。

快进不是另一个演算模式，而是让调度器连续处理下一批到期任务，直到目标时间或玩家中断条件。

### 8.2 事件驱动调度

每个持续行动保存下一次需要重新判断的时间：

- 到达路线检查点；
- 计划步骤完成；
- 伤势或状态到期；
- 秘境阶段转变；
- 市场、宗门或人口批处理边界；
- 新事实导致的紧急唤醒。

未发生变化的人物不在每分钟重新扫描全部大脑。

### 8.3 模拟精度

| 档位 | 对象 | 演算方式 |
|---|---|---|
| 聚合世界档 | 匿名人口、普通兽群、宏观经济 | 日/旬/月批处理 |
| 具名背景档 | 远方普通具名 NPC | 按计划完成时间和重要事实唤醒 |
| 活跃区域档 | 玩家所在及关注区域人物 | 小时/分钟检查路线、行动与相遇 |
| 焦点场景档 | 选中人物、对话、战斗和关键事件 | 分钟、秒或回合完整结算 |

升降档由相关度、重要事实、未完成承诺、独特资产、关系和距离共同决定，并使用迟滞；不能只因玩家快速移动而反复展开/归档。

不同档位共享同一事实和结算语义。降低精度允许压缩过程，不允许改写结果规则或丢失重要状态。

### 8.4 快进不变量

- 同种子、同输入下，逐步推进与快进到同一时间应产生等价权威结果；
- 快进不能跳过已经承诺的行动、秘境关闭、毒发、援军到达或战斗；
- 重大事件、玩家附近危险和关注人物危机可以自动暂停；
- UI 在高倍速下减少动画和标签，不减少世界结算。

## 9. NPC、移动与遭遇

### 9.1 NPC 空间感知

大脑只能读取个人能够知道的空间快照：当前位置、可见人物、已知道路、可用设施、感知到的危险、听说的异常和目标的推测位置。

NPC 不得因为行动节点需要目标，就直接读取目标真实位置。

### 9.2 行动类型

首轮空间行为至少支持：

- 前往地点、返回、巡逻、跟随、护送；
- 调查、追踪、伏击、逃离、封锁；
- 进入/离开场所或秘境；
- 开启、维持、攻击或尝试穿越结界；
- 探索未知区域与报告发现。

每个行为都进入计划、路线、验证、执行、结算和事实链，不直接改 `locationId`。

### 9.3 遭遇判定

遭遇由空间和时间重合产生：

- 同一场所同时在场；
- 路线在同一检查点重叠；
- 一方主动追踪、拦截或伏击；
- 视野、隐匿和警觉决定是否互相发现；
- 法律、关系、目标和风险决定是否交流、避让、偷袭或开战。

每次相遇不必进入战斗；每次战斗必须有真实参与者和冲突原因。

### 9.4 NPC 对 NPC 战斗

- 所有拥有正式档案的具名 NPC 使用同一战斗解析器真实结算；
- 玩家在场时显示完整战斗；关注但不在场时可显示摘要或只读回放；无人观察时无动画高速结算；
- 战力估算只用于大脑判断风险，不能直接替代具名胜负；
- 匿名军阵、兽群和人口可用群体模型；其中的宗主、天骄、玩家关系人物和独特资产持有者应抽出进入个人遭遇；
- 战后伤势、位置、死亡、逃跑、掉落、目击、关系和时间统一写回世界。

## 10. 地图 UI 与观察体验

### 10.1 总体布局

```text
┌────────────────── 顶栏：时间 / 倍速 / 玩家摘要 / 世界警报 ──────────────────┐
│ 左栏                    中央地图                          右侧观察器          │
│ 层级/地点树             保持常驻                         选中人物/地点/事件   │
│ 图层与筛选              语义缩放                         当前行动与原因       │
│ 当前区域 NPC            NPC/路线/异常                    进度、ETA、风险      │
│ 关注列表                地形与势力变化                   大脑/关系/历史       │
├────────────────── 底部抽屉：附近动态 / 传闻 / 编年史摘要 ──────────────────┤
```

现有三栏外壳可以渐进改造，但职责必须变化：地图不因查看 NPC 而消失，永久日志侧栏改为可折叠的底部时间线。

### 10.2 语义缩放

领域空间可以很深，但 UI 只需根据缩放和焦点自动切换表达：

| 观察尺度 | 主要显示 |
|---|---|
| 界域/大陆 | 大势力、种族分布、灵潮、战争和重大裂缝 |
| 地域 | 聚落、商路、迁徙、资源、危险、NPC 密度和重要人物 |
| LocalArea | 道路、地形、所有具名在场 NPC、路径和当前行动 |
| 聚落/宗门/遗迹 | 街区、建筑、设施、场所、人流和管辖 |
| 场所/场景 | 具体人物、交互、遮挡、战斗与即时环境 |

不要求用户通过七个独立页面逐级进入；滚轮、面包屑、搜索和“跟随人物”共享同一地图上下文。

### 10.3 NPC 标记语法

地图标记至少表达：

- 身份/种族轮廓；
- 势力色环；
- 当前行动图标；
- 路线和移动方向；
- 受伤、战斗、逃亡、闭关等重要状态；
- 关注或重大人物光环。

名称只对选中、悬停、关注和重大人物常显。密集区域聚合为人群或行动簇，放大后展开。

### 10.4 选中人物的“此刻”卡

右侧首先显示：

- 现在在哪里；
- 正在做什么；
- 为什么这样做；
- 目标人物/地点/物品；
- 已进行多久、预计何时改变；
- 当前风险和可能的中断条件；
- 最近导致该行动的事实。

大脑节点、候选得分、信念、记忆、关系和完整历史作为下级页签，不应压过“此刻”。

### 10.5 动态空间表现

- 秘境入口：显示阶段、稳定度、关闭窗口、进入者和争夺势力；
- 空间裂缝：显示影响范围、扩张方向和连接未知度；
- 结界：直接绘制边界，标明通行条件、耐久和感知遮蔽；
- 地形变化：使用新旧轮廓、伤痕、废墟和断路表达，不在事件结束后复原；
- 未知异常：只显示传闻范围和置信度，不能泄露真实坐标；
- 上帝观察模式：可显示权威真实状态；沉浸模式只显示玩家认知。

### 10.6 日志分层

1. **附近动态**：移动、吃饭、巡逻、交谈等即时观察，不长期保存全部文本。
2. **人物事实**：受伤、结仇、交易、突破、战斗、加入势力等可查询历史。
3. **玩家传闻**：玩家已经听说但未必真实或准确的信息。
4. **世界编年史**：重大、纪元级和长期影响事实。

普通出生不逐个播报；天赋异象、特殊血脉、重要家庭或与玩家相关的出生才进入显著日志。

### 10.7 倍速表现

- 1–4 倍：平滑人物移动和短时行动；
- 8–16 倍：减少标签，保留路线、进入/离开、冲突和异常脉冲；
- 极高速：停止大量个体动画，改为人流、热力、事件波纹和关注人物轨迹；
- 暂停后自动总结该地区在快进期间发生的关键变化。

## 11. 权威数据与存档边界

### 11.1 必须持久化

- 动态创建的空间节点和稳定 ID；
- 当前有效连接及其状态；
- 动态空间特征和生命周期；
- 永久或长期地图差量；
- 人物位置、旅行状态和行动计划；
- 下一次生命周期/行动唤醒时间；
- 世界修订号、已提交 Outcome ID 和随机种子；
- 结构化事实、人物认知和必要历史。

### 11.2 不应持久化

- 地图 SVG/Canvas 节点；
- NPC 图标位置插值；
- 聚合热力图和聚类结果；
- 当前鼠标悬停、临时筛选和动画；
- 可由权威空间和时间确定性重建的渲染快照。

### 11.3 保存策略

采用“当前状态快照 + 不可变事实 + 稀疏地图差量”，不采用纯事件溯源：

- 快照保证读档速度；
- 事实保证历史、因果和 AI 上下文；
- 差量保证地图变化与基础地图分离；
- 定期压缩已结束的短期覆盖，但不能删除其历史事实。

## 12. 核心不变量

1. 世界时间单调递增，任何结果不能重复推进时间。
2. 一个实体同一时刻只能有一个权威位置或一个明确的途中状态。
3. 所有位置必须解析到存在的空间节点；所有连接端点必须有效。
4. 关闭、坍塌或删除空间前必须处理内部实体，不能把人物悬空。
5. 地图变更、人物位移、资产变化、伤亡和事实必须原子提交。
6. 事实只能在世界差量提交成功后生成。
7. 快进和逐步推进在同种子、同输入下产生等价权威结果。
8. 玩家是否观察不能改变 NPC 的胜负规则、物品归属和死亡。
9. 远处降精度不能丢失稳定身份、关系、长期伤势、资产、计划和重大事实。
10. 渲染投影不能整体覆盖权威档案。
11. 沉浸视角不能读取玩家尚未知晓的秘境位置、NPC 计划或秘密事实。
12. 正式玩法中的 NPC、地点、物品和异常必须来自权威世界；空数据应显示空状态，不得偷偷生成演示数据。

## 13. 七类领域风险

### 13.1 不变量风险

最危险的是一个人物同时出现在场所和途中、入口关闭后人物无位置、同一秘境重复生成、快进重复结算。必须提供世界一致性检查器，能报告悬空位置、无效连接、重复 Outcome 和过期路线。

### 13.2 原子性风险

秘境开启可能同时创建入口、内部空间、事实和调度任务；灾害可能同时毁路、伤人、迁徙和改变资源。必须先在隔离草案上全部验证，再一次发布；失败不能留下半个世界。

### 13.3 并发风险

多名 NPC 可能同时抢占入口、穿过即将关闭的裂缝或争夺同一资源。以世界修订号、提交顺序、行动开始时间和注入随机种子决定结果，不依赖对象遍历顺序。

### 13.4 副作用风险

路径失效、强制位移、人物死亡和空间坍塌属于高影响副作用。每项必须产出明确原因和补偿规则；UI 通知和 AI 文案不能早于权威提交。

### 13.5 信任边界风险

AI 提议、MOD 内容和自然语言命令均为不可信输入。只能引用已存在实体和允许的空间操作，通过预算、权限、范围、持续时间和规则校验后进入 Outcome。

### 13.6 可观测性风险

最糟糕的失败不是崩溃，而是世界静默跳人、快进漏行动或地图图标与事实不一致。应记录：行动唤醒原因、路线修订号、空间变更原因、Outcome 提交结果、重规划原因、模拟档位切换和事实引用。

### 13.7 性能风险

热路径是全 NPC 扫描、全地图重算、每格事件抽取和 UI 全量标记。对策：事件驱动唤醒、空间索引、局部差量、聚类投影、焦点泡泡和生命周期下一转变时间。

## 14. 架构决策记录

### ADR-SP-001：空间图替代固定层级枚举

- **决策**：领域空间使用可嵌套节点和连接图；UI 层级仅作为投影视图。
- **背景**：固定五层无法表达 LocalArea、地下、口袋空间和动态连接。
- **选项**：继续增加枚举；每种地图单独建模；统一空间图。
- **选择**：统一空间图。
- **代价**：契约和位置迁移成本较高，但消除后续每增加一种空间就重构全链路的问题。
- **回滚**：在迁移期由适配器继续输出旧 `MapLayer/LocationRef`，不立即删除旧字段。

### ADR-SP-002：基础地图 + 稀疏差量

- **决策**：静态世界定义与动态地图状态分离。
- **背景**：直接修改生成网格难以迁移、回放和解释；纯事件溯源又会增加读档和重放成本。
- **选项**：整图覆盖；纯事件溯源；快照加差量与事实。
- **选择**：快照加稀疏差量与事实。
- **代价**：需要差量合并和压缩，但能稳定存档并保留历史。
- **回滚**：动态功能关闭时仍可只加载基础地图和已兼容的永久差量。

### ADR-SP-003：秘境作为独立空间域

- **决策**：秘境通过 PortalLink 与主世界连接，不作为固定线性层级。
- **背景**：秘境大小、内部层级、时间和入口生命周期不同。
- **选项**：Dungeon 场所；固定 SecretRealm 层；独立空间域。
- **选择**：独立空间域，小型秘境允许退化成单场景。
- **代价**：必须处理关闭时内部人物和跨域时间。
- **回滚**：首版只启用单入口、单出口、统一时间倍率，复杂规则后置。

### ADR-SP-004：事件驱动的多精度调度

- **决策**：按下一唤醒时间推进，不按分钟扫描全部 NPC。
- **背景**：具名 NPC 数量增加后，全量高频大脑不可承受。
- **选项**：月度全扫；全世界实时 tick；事件驱动加焦点高频。
- **选择**：事件驱动加焦点高频。
- **代价**：调度与重规划更复杂，但快进和实时可以共享一条时间链。
- **回滚**：保留月度批处理作为聚合系统，不作为具名移动入口。

### ADR-SP-005：地图中心的观察工作台

- **决策**：地图常驻，人物、地点和事件使用侧边观察器，日志进入底部抽屉。
- **背景**：切换到 NPC 页会失去空间上下文，无法持续观察行动。
- **选项**：继续页签切换；多窗口；地图中心工作台。
- **选择**：地图中心工作台。
- **代价**：需要重新分配现有面板职责，但可渐进迁移。
- **回滚**：旧独立 NPC 页面暂时保留为详细档案入口。

## 15. 实施阶段与质量门

### Phase 0：冻结基线与兼容边界

**输入**：现有地图、时间、位置、聚落、NPC、存档和未提交止血修改。

**任务**：

- 记录当前生产调用链和旧存档样本；
- 冻结新旧位置之间的适配规则；
- 明确哪些临时/旧 API 允许迁移期存在；
- 标记正式路径中的假数据和临时 NPC 来源；
- 运行一次基线检查，不在此阶段修外围问题。

**输出**：迁移清单、兼容矩阵、回滚点。

**退出标准**：可以指出每一种位置、地图和旅行状态的权威来源；没有未解释的存档字段。

**回滚**：纯审计与适配准备，不改变正式行为。

### Phase 1：统一空间契约

**输入**：Phase 0 兼容矩阵。

**任务**：

- 建立空间节点、父子包含、连接、空间地址、坐标尺度和连续旅行状态；
- 建立动态空间状态、特征、差量、生命周期和调度时间契约；
- 扩展世界状态和存档迁移；
- 提供旧节点、旧场所、旧六边形和聚落地图到新空间的只读适配；
- 暂不切换 UI 和正式移动。

**输出**：单一空间语义、兼容读取、迁移后的存档。

**风险**：存档损坏、位置悬空、重复权威。

**退出标准**：所有现有人物与玩家位置都能解析到同一空间树；旧存档迁移后不改变人物所在地点。

**回滚**：保留旧字段读取，新增字段不作为正式写入口。

### Phase 2：统一移动、时间与调度

**输入**：统一空间契约、权威时钟、NPC 计划。

**任务**：

- 建立统一距离、速度、路径和耗时解析；
- 玩家与 NPC 使用同一旅行状态和空间检查点；
- 将 NPC 月度跳格/随机落脚迁移为真实行动计划；
- 建立下一唤醒时间队列和路径失效重规划；
- 普通流逝、旅行和快进统一进入权威时钟；
- 保留月度系统用于人口、经济等聚合批处理。

**输出**：连续移动、真实 ETA、逐步与快进等价。

**风险**：时间重复推进、NPC 卡路、性能下降。

**退出标准**：观察 NPC 能看到出发、途中、到达和原因；玩家移动会推动相同世界时间；关闭旧随机落脚正式入口。

**回滚**：通过迁移开关回到旧移动展示，但不回退已保存的绝对时间和空间 ID。

### Phase 3：动态空间与地图变更

**输入**：空间契约、调度器、WorldOutcome。

**任务**：

- 实现空间特征生命周期和地图差量解析；
- 首批只做三种代表性能力：小型秘境入口、局部结界、道路/地形灾害；
- 实现连接开启/关闭、范围效果、受影响路线重规划和内部实体处理；
- 事实生成严格晚于原子提交；
- 将旧“秘境开启/天灾”概率描述迁移为条件化触发或暂时禁用正式效果。

**输出**：地图可以真实出现、变化和留下历史。

**风险**：半提交、人物悬空、重复生成、全地图重算。

**退出标准**：三类动态变化均可存档、读档、到期、影响移动并产生可追溯事实。

**回滚**：停止生成新动态特征；已存在特征按兼容规则安全关闭或冻结，不能直接删除。

### Phase 4：NPC 大脑与世界反应

**输入**：动态空间、认知、计划与具名战斗。

**任务**：

- 将空间感知、已知道路、危险、异常和地点机会接入大脑；
- 增加调查、进入、封锁、逃离、维护/攻击结界等空间行动；
- 相遇由路线和时间产生，偷袭失败可转入真实战斗；
- NPC-NPC 具名战斗无动画高速结算并回写地图、人物与事实；
- 匿名人口继续使用群体模型；
- 禁止正式链路创建临时人物补足场面。

**输出**：地图变化会真实改变 NPC 决策，并形成连续故事。

**风险**：大脑计划抖动、信息泄露、远处战斗性能。

**退出标准**：不同性格/身份 NPC 对同一秘境做出可解释的不同选择；战斗前后人物、资产和地点一致。

**回滚**：关闭新增空间节点装配，NPC 回到已有大脑节点，但动态空间仍保持权威存在。

### Phase 5：地图观察工作台

**输入**：权威空间、人物行动、认知与事实查询。

**任务**：

- 将地图扩展为主要工作区；
- 实现语义缩放、面包屑、图层、搜索、关注和人物聚类；
- 点击 NPC 在右侧显示“此刻”卡，地图不切走；
- 绘制路径、ETA、动态结界、裂缝范围、秘境阶段和地形伤痕；
- 将日志拆为附近动态、人物事实、玩家传闻和编年史；
- 倍速变化只降低表现密度，不改变演算；
- 左键选择，右键或明确按钮行动。

**输出**：玩家能舒适地观察世界运行，而不是靠日志猜测世界。

**风险**：标记拥挤、响应速度、信息泄露、交互误触。

**退出标准**：地图、NPC 观察器和时间线可同时使用；局部所有具名 NPC 可定位、选中、跟随和解释。

**回滚**：保留旧地图面板入口，新的观察器作为可切换布局，稳定后再移除旧职责。

### Phase 6：垂直切片——“秘境现世”

**输入**：Phase 1–5 全部能力。

**场景**：一处已有潜伏原因的小型秘境经历征兆、现世、人物响应、争夺、战斗、关闭和遗迹化。

**必须验收**：

1. 秘境不是直接抽出结果，而是由真实条件进入征兆。
2. 入口在真实 LocalArea 生成并可寻路。
3. 玩家和 NPC 使用同一进入与移动规则。
4. NPC 是否前往能从认知、性格、关系和利益解释。
5. 消息只传播给可能知晓的人，不全世界同步得知。
6. 至少两名具名 NPC 因路线/目标形成真实相遇。
7. 偷袭、逃跑或争夺进入同一具名战斗解析器。
8. 伤势、死亡、资产、关系和耗时原子回写。
9. 秘境关闭前处理内部人物，不产生悬空位置。
10. 入口关闭和残留遗迹在地图与事实历史中可见。
11. 存档读档后阶段、内部人物和剩余时间一致。
12. 正常推进与快进在同种子下得到等价权威结果。
13. UI 能同时观察地图、选中人物行动和相关事实链。
14. 全过程没有临时 NPC、无来源资产和先果后因日志。

**退出标准**：上述 14 项全部通过；不能用硬编码剧情脚本绕过系统。

### Phase 7：收敛、性能与清理

**任务**：

- 评估 800、1500 具名 NPC 和高倍快进；
- 检查调度队列、空间索引、渲染聚类和存档体积；
- 删除已经证明无调用的旧正式入口，但保留必要迁移读取；
- 更新上位架构文档和当前状态；
- 运行最终全量测试、类型检查、构建和人工试玩清单。

**退出标准**：没有两套正式位置/旅行语义；性能达到约定基线；旧存档可读；完整切片可重复试玩。

**回滚**：清理必须独立于功能提交；出现回归可单独恢复兼容入口。

## 16. 测试节奏

遵循“阶段质量门”，不走一步就跑一次全量测试：

- Phase 0：一次现状基线；
- Phase 1：位置、迁移、不变量的针对性测试；
- Phase 2：时间、移动、快进等价的针对性与阶段集成测试；
- Phase 3：动态空间原子性和生命周期测试；
- Phase 4：NPC 行动、遭遇和战斗回写集成测试；
- Phase 5：交互关键路径和必要 UI 测试；
- Phase 6：完整垂直切片测试；
- Phase 7：一次最终全量测试、类型检查和构建。

出现高风险缺陷时补最小回归测试；普通布局和机械调整不要求逐文件测试。

## 17. 实现授权边界

如果用户授权同一模型连续完成本方案，允许修改 contracts、engine、UI、persistence、tests 和 docs，但必须遵守：

1. 按 Phase 0 → 7 顺序推进，不因追求可见效果跳过权威空间和迁移；
2. 每个阶段结束先对照退出标准并汇报，再进入下一阶段；
3. 不覆盖或回退工作区已有无关修改；
4. 不在正式路径生成临时 NPC、假地点、假库存或无法回写的演示事件；
5. 不让 AI 直接修改世界状态；
6. 不让 UI 自己推进时间、改变人物位置或制造事实；
7. 不保留两套长期并行的正式移动/地图语义；迁移开关必须有删除条件；
8. 发现核心假设错误、旧存档无法无损迁移或现有改动冲突时停止，先修订 ADR；
9. 未经用户明确授权，不提交、推送或发布；
10. Phase 7 完成后停止，不顺手扩展天气、跨界、更多秘境内容、AI 对话或渡劫。

## 18. 假设与重新规划条件

当前方案依赖以下假设：

- 游戏仍以约 800–1500 个具名 NPC 加匿名人口聚合为主要规模；
- 单机、单权威世界，不需要多人服务器并发；
- 基础地图大部分稳定，长期变化是稀疏局部差量；
- 当前 IndexedDB 存档仍需兼容；
- 战斗、世界事务、NPC 大脑和事实账本的现有收敛成果继续保留；
- UI 不追求全世界逐帧显示每个人，而追求可搜索、可定位、可跟随和局部全显。

若未来要求“所有地形单元都可实时永久破坏”“数万具名 NPC 同时逐秒演算”或“多人共同修改同一世界”，必须返回架构阶段重新设计存储、并发与模拟边界，不能在本方案上继续堆补丁。

## 19. 完成定义

该重构完成时，玩家应能回答：

- 我看到的这个人是谁，他从哪里来，为什么正在这里？
- 他要去哪里，多久到，会因什么改道？
- 这处秘境或裂缝为什么出现，谁知道，谁在争夺？
- 地图哪里真的发生了变化，对人和社会造成了什么影响？
- 一场冲突是真实打过，还是日志直接宣布了结果？
- 快进期间世界做了什么，为什么得到现在的结果？
- 我不知道的信息究竟是不存在，还是尚未被我发现？

如果这些答案都能从权威状态、人物大脑、空间变化和事实链中追溯，而不依赖临时数据或预写剧情，TaoSim 才真正具备区别于普通 RPG 的“活修仙世界”。
