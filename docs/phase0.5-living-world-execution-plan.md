# Phase 0.5：活世界底座修复执行方案

> 状态：已完成产品方向确认，可进入实施
> 日期：2026-08-10
> 上位约束：[统一修仙世界模拟架构方案](systemic-cultivation-world-blueprint.md)
> 前置审计：[Phase 0 契约层审计](phase0-audit/06-migration-acceptance-plan.md)
> 实施后复核：[Phase 0.5：运行时接线与活世界收口方案](phase0.5-runtime-closeout-plan.md)（P5/P6/P7 尚未形成生产闭环时，以此收口方案为准）

## 1. 本轮目标

本轮不继续扩展渡劫、夺舍、AI 对话或更多事件模板，而是修复实际试玩暴露出的“世界演算存在，但玩家感知不到同一个活世界”的问题。

完成后必须成立：

1. 玩家、NPC、势力、经济和地图只使用一个权威世界时间；
2. 闭关、等待和加速是整个世界的可中断快进，不是只推进玩家的隔离时间；
3. 所有具名 NPC 都持续拥有需求、目标、计划、当前位置和下一次行动，不靠随机事件替代人生；
4. 远方 NPC 可以低频或按计划到期结算，但不得失去稳定身份、意愿和因果；
5. 天机城等聚落拥有可进入的小地图、真实场所和动态在场 NPC 列表；
6. 普通人从气血 5、灵力 0 的凡人尺度起步，境界对完整战斗与移动能力产生统一派生；
7. 日志来自已结算事实，并按世界新闻、本地消息、关注人物时间线分层；
8. 战斗 AI 根据候选行为效用决策，不再只是固定优先级脚本。

## 2. 已完成的临时修正

以下改动已经存在，实施时不得回退，但也不得误认为统一时间已经完成：

- 玩家可见的 `fastForward` 已从 `Isolated` 改为 `World`；
- 人口补充时，普通修士入世不再逐个写入事件流；特殊先天、变异灵根或天灵根才产生入世报道；
- 真实世界 NPC 的战斗投影与 `WorldOutcome` 差量回写已有第一版；
- `WorldTime`、`TimeElapsed`、`LocationRef` 等契约已有骨架，但 `WorldState` 尚未真正以绝对时间作为权威。

## 3. 冻结的产品决策

### 3.1 凡人与修士数值

- 普通人基准气血为 5；未引气入体时灵力上限为 0；
- 凡人必须是明确的修炼阶段，不能继续伪装成 `QiRefinement_1`；契约应提供 `Mortal` 或等价且唯一的未入道状态；
- 灵根表示吸收与转化灵气的潜力，不等于出生自带灵力；
- 若开局身份明确已经是修士，则通过统一派生属性计算修士数值，不强制回到凡人 5/0；
- 种族、年龄、体质、血脉、伤病、功法、装备和境界共同修正派生属性；
- 境界必须影响气血、灵力、攻击、防御、速度、神识、寿元和能力门槛，不能只增加 HP；
- 具体倍率由基准战斗反推，不在契约中散落魔法数字。

### 3.2 地图层级

目标层级固定为：

```text
Cosmos
→ Continent
→ Region
→ Settlement / Area
→ Venue
→ Scene
```

- 当前大陆六边形网格属于 Region，不承担城内步行和房间级探索；
- 天机城、宗门、坊市、秘境入口属于 Settlement / Area；
- 百宝阁、酒楼、拍卖场、城门、民居、暗巷属于 Venue；
- 战斗、室内互动、拍卖现场属于 Scene；
- 现有 `Venue` 列表不能冒充聚落小地图。

### 3.3 NPC 活动语义

“所有 NPC 都会活动”定义为：每个具名 NPC 始终具有可查询的当前意愿和行动状态，而不是每个渲染帧遍历所有 NPC。

每个具名 NPC 至少拥有：

- needs：安全、修炼、寿元、财富、关系、名望等压力；
- goal：当前主目标；
- plan：完成目标所需的步骤；
- currentAction：正在执行的行为；
- location / route：当前位置或旅行路线；
- nextDecisionAt：下一次重新决策的权威时间；
- memories / factRefs：影响决策的重要事实引用；
- interruptionPolicy：遇到危险、关系事件、世界灾害时是否中断原计划。

远方人物按计划到期结算；附近、关注和现场人物提高更新精度。精度可以不同，事实和身份不能分裂。

### 3.4 快进语义

- 闭关、修炼、等待和时间加速都调用同一个世界推进入口；
- 玩家在闭关期间只是不能进行常规操作，世界绝不停止；
- 快进必须可以被死亡风险、仇敌来袭、宗门召集、重大关系事件、资源耗尽、突破条件达成等中断；
- 快进结果提供摘要，不把全部低价值流水账一次性灌给玩家；
- `Isolated` 只允许内部预览或测试使用，不得从正式玩法入口调用。

## 4. 模块边界

| 模块 | 唯一职责 |
|---|---|
| World Clock & Scheduler | 权威绝对时间、时间边界调度、快进、中断和计划到期执行 |
| Derived Attributes | 从生命形态、基础属性、境界、功法、装备和状态计算战斗/移动派生值 |
| Spatial World | 地图包含关系、真实距离、路线、聚落小地图、位置索引和在场查询 |
| NPC Mind | 需求、目标、计划、行为选择、重规划和远近精度调度 |
| Fact & Attention | 事实账本、个人时间线、关注人物、新闻/传闻筛选和摘要 |
| Battle Decision | 候选战斗行为、效用评分、性格与目标权重，不负责直接改写世界 |
| World Transaction | 玩家、NPC、位置、资产、关系、时间和事实的原子提交 |

任何模块不得绕过 World Transaction 直接制造已经发生的历史。

## 5. 架构决策

### ADR-P05-1：玩家跳时等于世界快进

- **Decision**：正式玩法不再存在“只推进玩家”的时间模式；闭关和等待提交一个带结束条件的世界快进请求。
- **Context**：现有旅行、修炼、实时流逝和月度世界演算仍有多条入口，导致玩家变老而 NPC 不动。
- **Options**：继续同步多个时钟；只在闭关后补算；唯一时钟与统一调度。
- **Chosen**：持久化绝对分钟数，所有行为提交耗时，跨日/月边界触发对应调度器。
- **Tradeoff**：需要迁移存档并改造所有耗时入口；换取确定、可回放的统一世界。
- **Rollback**：保留旧年月字段作为只读兼容投影，禁止重新成为写入权威。

### ADR-P05-2：NPC 使用计划调度，不使用事件抽签代替行动

- **Decision**：具名 NPC 的世界变化由需求形成目标、目标生成行动计划、行动到期后结算产生。
- **Context**：当前月度循环虽然产生大量事件，但人物连续性弱，测试统计事件数量也无法证明人生真实。
- **Options**：继续概率事件；所有 NPC 每帧完整模拟；计划队列与分层结算。
- **Chosen**：计划队列；现场高精度、远方按到期时间结算，二者写入同一事实。
- **Tradeoff**：需要维护计划生命周期和中断规则；换取可解释行为与可扩展性能。
- **Rollback**：迁移期可把旧月度行为包装成低优先级计划解析器，但不得直接生成叙事结果。

### ADR-P05-3：新增聚落地图，而不是继续膨胀 Region 网格

- **Decision**：在 Region 与 Venue 之间建立 Settlement / Area，小地图负责城市、宗门、坊市和秘境入口内部移动。
- **Context**：当前 Venue 只是场所列表，玩家无法看到天机城结构、当前人物和人物移动。
- **Options**：Region 网格继续细分；场所列表；独立聚落图。
- **Chosen**：独立聚落图，地点节点与道路具有距离，NPC 和玩家共享位置引用。
- **Tradeoff**：增加地图切换和位置迁移；换取局部社会和遭遇的空间真实性。
- **Rollback**：首版只实现天机城，其他聚落继续使用旧列表适配器。

### ADR-P05-4：战斗与移动数值统一派生

- **Decision**：HP、灵力、攻击、防御、速度、神识等不再由创建器和 UI 分散写死，统一从领域输入计算。
- **Context**：当前玩家固定 100/100，攻击主要是装备攻击加常数，境界成长没有全方位进入战斗。
- **Options**：继续逐功能加成；保存全部派生值；集中计算并缓存。
- **Chosen**：权威输入 + 纯函数派生 + 可失效缓存；存档保存输入和长期状态，不保存可重建派生值。
- **Tradeoff**：旧存档显示数值可能变化；换取统一校准和玩家/NPC 同规则。
- **Rollback**：保留旧数值适配器作为一个迁移版本，禁止新代码继续引用。

## 6. 领域风险

### 不变量

- 世界绝对时间只增不减，同一动作不得重复计时；
- 同一实体只能位于一个地点或一条旅行路线；
- NPC 的目标、行动、位置和事实在同一时间点不得互相矛盾；
- 派生属性由同一组权威输入确定，玩家与 NPC 使用同一公式；
- 日志只能描述已提交事实；普通人口变化不能污染世界新闻；
- 关注人物改变保留与展示精度，不给予其概率特权或剧情护甲。

### 原子性

- 行动结束时，耗时、位置、资源、关系、状态和事实必须全有或全无；
- 快进中断必须停在最后一次完整提交之后；
- NPC 购买、旅行、战斗、死亡不能留下半扣款、双位置或幽灵计划。

### 并发

- 实时流逝、手动快进、玩家操作和自动存档不能同时写权威状态；
- 同一 NPC 同时只能有一个可执行主计划；
- 加载存档后，旧定时器和旧计划执行器必须失效。

### 副作用

- UI 动画、日志展示和 AI 文案失败不得回滚已经提交的世界事实；
- 自动存档失败必须可见，但不能重复执行已经完成的行动。

### 信任边界

- 存档、MOD 和未来 AI 提交的意图必须通过同一行动验证器；
- AI 只能提出目标或意图，不能直接写位置、数值、关系或事实。

### 可观测性

至少记录：推进原因、起止时间、执行的调度边界、计划到期数、中断原因、事实数、各精度 NPC 数、单阶段耗时和失败原因。

### 性能

- 禁止每条规则独立扫描全体 NPC；
- 维护地点、计划到期时间、关系和关注对象索引；
- 快进分块执行并向 UI 让出控制权；
- 远方 NPC 按 `nextDecisionAt` 调度，不逐分钟遍历。

## 7. 实施顺序与质量门

### P0：冻结基线与特征测试

**输入**：当前脏工作树、Phase 0 审计、现有测试。

**输出**：可复现的行为基线、失败测试和性能基准报告。

**主要风险**：误把既有脏改动归为本轮修改，或用错误测试固化缺陷。

**任务**：

1. 不覆盖或回滚现有用户修改；记录本轮起始 diff；
2. 为以下现状补特征测试：快进会推进世界、地图移动目前不推进世界、普通出生过滤、观察人物当前只是查询；
3. 修复现有渡劫测试夹具的 4 个 TypeScript 类型错误，使生产构建和包含测试的类型检查同时通过；
4. 记录 800/1500 NPC 的 1 年、10 年快进性能基线。

**质量门**：现有测试行为被锁定；新增失败测试准确覆盖待修缺口；不得先改实现再补测试。

**回滚**：仅删除本阶段新增测试与报告，不改变生产行为。

### P1：权威世界时钟与可中断快进

**输入**：已有 `WorldTime`/`TimeElapsed` 契约、旧年月状态、月度引擎。

**输出**：持久化绝对时钟、统一调度入口、可中断快进和存档迁移。

**主要风险**：同一行为重复推进时间、旧档迁移漂移、实时计时器与快进并发写入。

**任务**：

1. 将绝对 `elapsedMinutes` 正式纳入 `WorldState` 权威数据并升级存档版本；
2. 年、月、日、时辰全部由绝对时间投影；旧 `currentYear/currentMonth` 在迁移期只读兼容；
3. 建立唯一 `advanceWorldTime`/调度入口，统一玩家行动、移动、战斗、炼丹、修炼、实时流逝和快进；
4. 跨越每日、每月、每年边界时只执行对应调度，不逐分钟扫描世界；
5. 将快进实现为可取消、可显示进度、可被条件中断的分块任务；
6. 正式玩法入口禁止调用 `Isolated`；
7. 同种子下“一次快进 12 个月”和“逐月推进 12 次”必须得到等价权威状态和事实。

**质量门**：移动 60 天后玩家、NPC、市场和宗门都经过相同 60 天；保存读取后时间和待执行计划不漂移。

**回滚**：读旧年月投影，保留旧月度结算适配器；不可恢复成多写入口。

### P2：统一派生属性与境界尺度

**输入**：Character/NpcRecord、种族扩展点、境界、装备、功法、长期状态。

**输出**：显式凡人阶段、统一 `DerivedStats`、版本化数值迁移和战斗基准。

**主要风险**：旧存档战力突变、两套公式并存、跨境界曲线失控。

**任务**：

1. 在领域契约中加入显式 `Mortal`/未入道阶段，禁止继续把所有人初始化为 `QiRefinement_1`；
2. 定义权威基础属性与 `DerivedStats`，集中计算 HP、灵力、攻击、防御、速度、神识、命中、闪避和寿元；
3. 人族健康成年凡人基准为气血 5、灵力 0；儿童、老人、异族和伤病通过输入修正；
4. 引气入体后才建立灵力池；境界同时施加量变倍率与能力门槛；
5. 移除创建器、UI、NPC 投影和战斗公式中的 100/10 等重复权威魔法数字；
6. 玩家与 NPC 共用派生函数；场景投影只叠加临时状态；
7. 以目标 TTK 校准：同境界、基础装备、正常 AI 的战斗不应长期刮痧或一击结束；跨大境界保持明显压制但允许有世界内原因的例外。

**质量门**：同输入确定同输出；境界升级影响全部规定维度；新建凡人显示 5/0；旧存档迁移不产生负数或 NaN。

**回滚**：提供一个版本化旧数值迁移适配器，不允许双公式长期共存。

### P3：空间、真实距离与天机城聚落地图

**输入**：现有 Cosmos/Continent/Region/Venue、`LocationRef`、天机城场所目录。

**输出**：层级位置契约、真实旅行耗时、天机城聚落图和动态在场人物查询。

**主要风险**：旧 `locationId` 与新层级形成双权威，或城内 NPC 再次变成临时生成物。

**任务**：

1. 扩展位置契约以表达 Region、Settlement/Area、Venue、Scene 和 Route；
2. 将当前 Venue 列表降为聚落图中的具体地点；
3. 为天机城实现首个聚落小地图：城门、主街、百宝阁、拍卖场、酒楼、客栈、民居、暗巷等节点与道路；
4. 边和格子记录物理距离，旅行耗时由距离、速度、移动方式、道路、地形、天气、伤势、负重和队伍计算；
5. 玩家与 NPC 使用同一位置和路线系统；
6. 城内当前 NPC 列表只读取真实在场实体，展示其可感知身份、当前位置和当前行为；
7. 删除或封堵玩家可遇见的临时 `NPCGenerator.generate()` 人物路径；生态妖兽也必须来自世界生态实体或明确的群体投影。

**质量门**：进入天机城可见真实小地图；NPC 在不同场所间移动时列表同步变化；读档后位置和路线一致。

**回滚**：其他聚落继续用旧场所列表，天机城可通过短期功能开关回退；位置权威契约不可回退。

### P4：NPC Mind 与计划调度器

**输入**：NPC 档案、关系、记忆事实、位置、资产、组织、世界时间。

**输出**：持久化 MindState、计划队列、行为解析器和中断机制。

**主要风险**：计划与位置事实矛盾、全量扫描导致性能崩溃、概率事件继续偷渡结果。

**任务**：

1. 为每个具名 NPC 建立持久化 MindState；
2. 将需求压力转化为目标，将目标拆成带前置条件、成本、地点和期限的计划；
3. 当前行为到期后由规则结算并产生 WorldOutcome/Fact，再重新规划；
4. 支持修炼、求职/宗门职责、购买、旅行、拜访、闭关、求医、寻仇、求偶、逃难等最小行为集；
5. 现场人物执行高精度行动；远方人物按计划到期批处理，但不得直接抽取完整故事结果；
6. 实现危险、关系、资源和组织命令导致的计划中断；
7. 旧月度概率规则迁移为压力、候选行为或结算条件，逐项禁止直接产生日志事实。

**质量门**：任取一个 NPC 都能回答“为什么在这里、正在做什么、下一步去哪、依据哪些事实”；同种子和输入可重放。

**回滚**：旧规则可作为低优先级候选行为提供器，不能再直接改写叙事结果。

### P5：关注人物、事实保留与日志降噪

**输入**：事实账本、MindState、玩家知识边界、事件模板。

**输出**：关注人物契约、三层信息流、事实驱动时间线和快进摘要。

**主要风险**：关注机制意外改变人物命运，或日志泄露隐藏血脉、转世和远方秘密。

**任务**：

1. 将“选中人物”升级为可持久化关注/取消关注；
2. 关注只提高事实保留、查询与展示精度，不改变人物运气、行动概率或死亡规则；
3. 建立三条输出：世界大事、本地消息/传闻、关注人物时间线；
4. 普通出生、日常吃饭、普通走动不进入世界新闻；特殊天赋和异象只报道可观察现象，不直接泄露隐藏转世/血脉真相；
5. 人物时间线从 Fact 和重要状态差异生成，不从临时 UI 日志拼接；
6. 快进结束生成摘要，并在玩家相关或重大中断发生时暂停。

**质量门**：关注同一 NPC 三年，可以看到连续目标、旅行、关系和重要结果；取消关注不删除已发生事实；普通出生不刷屏。

**回滚**：保留现有日志 UI 作为只读兼容视图，事实账本继续权威。

### P6：战斗 AI 与数值接入

**输入**：统一派生属性、战斗原子、人物性格、战斗目标和场景。

**输出**：候选行为生成器、效用评分器、决策诊断与正式默认 AI。

**主要风险**：AI 读取全知信息、决策不确定导致无法复现、评分计算拖慢回合。

**任务**：

1. 枚举当前合法候选行为：技能、普攻、移动、防御、道具、逃跑；
2. 对预期伤害、击杀机会、控制收益、生存风险、资源成本、位置、克制和后续回合进行效用评分；
3. 性格、关系、任务和战斗目的调整权重，例如复仇者更冒进、护送者优先保护、惜命者更早撤退；
4. AI 不读取不可见信息，不获得额外命中或资源；
5. 全部伤害和行动经济接入统一派生属性；
6. 保留确定性种子和决策诊断信息，便于复盘“为什么这么做”。

**质量门**：AI 能在测试场景中选择补刀、控制、脱离危险格、节省资源和逃跑；不得只按技能数组顺序或倍率最大值选择。

**回滚**：旧固定优先级 AI 只作为故障降级，不作为正式默认。

### P7：天机城活世界垂直切片

**输入**：P1-P6 的统一时间、数值、空间、NPC 计划、关注和战斗。

**输出**：可从 UI 连续体验、可保存恢复的天机城活世界垂直切片。

**主要风险**：跨模块部分提交、通过脚本硬演剧情、只在演示存档中成立。

实现并验收以下连续场景：

1. 一名真实 NPC 因丹药不足形成购买目标；
2. 他从当前地点启程前往天机城；
3. 玩家在城内小地图和当前 NPC 列表中看到他抵达百宝阁；
4. 商品、灵石和所有权真实转移；
5. 玩家关注他后可看到目标形成、旅行、交易和后续修炼；
6. 玩家闭关一年，整个世界共同快进；期间该 NPC 和其他人物继续行动；
7. 若发生玩家相关重大事件，快进中断；否则返回阶段摘要；
8. 玩家移动、战斗或袭击该 NPC 后，伤势、关系、位置、资产和事实原子回写；
9. 保存、退出、读取后，人物计划、时间、位置和历史连续。

**质量门**：不出现临时人物、双位置、时间不同步、普通出生刷屏、整体对象覆盖或剧情卡先果后因。

## 8. 全局验收标准

1. 新建健康成年凡人气血为 5、灵力为 0；已入道角色按境界派生；
2. 快进 12 个月与逐月推进 12 次在同种子下得到等价权威状态；
3. 移动产生的日数真实推进整个世界，而不是只增加玩家年龄；
4. 快进可取消、可中断、可显示进度，正式玩法无 `Isolated` 调用；
5. 天机城有可交互小地图和真实动态 NPC 列表；
6. 玩家遭遇的具名人物全部可从 WorldState/EntityDirectory 追溯；
7. 任意具名 NPC 都有当前目标、行动和下一次决策时间；
8. 关注人物三年时间线具有连续因果，普通出生不进入全局新闻；
9. 境界提升至少影响气血、灵力、攻击、防御、速度、神识和寿元；
10. 战斗 AI 在基准场景中表现出目标、资源、位置和生存判断；
11. 存档迁移、读写往返、重复提交和中断恢复测试全部通过；
12. 1500 具名 NPC 快进 10 年不崩溃、不无限增长、不产生悬空引用；开发机基准目标不超过 10 秒，并记录各阶段耗时；
13. 快进执行分块向 UI 让出控制权，单个同步计算块目标不超过 50ms；
14. 生产构建、各 workspace 类型检查和全部自动测试必须全绿；不得把超时或测试夹具错误标成“已知问题”后交付。

## 9. 禁止事项

- 禁止继续用事件模板直接决定人物已经经历了什么；
- 禁止新增第二套时间、位置、数值或 NPC 权威；
- 禁止把所有 NPC 展开为完整 Character 常驻和存档；
- 禁止用“远方概率骰子”抹掉 NPC 的目标、计划和资产，只允许降低结算频率；
- 禁止关注人物获得剧情保护或隐藏概率加成；
- 禁止为了完成小地图再生成一套无世界身份的城内 NPC；
- 禁止在本轮扩展完整种族内容、LLM 对话、渡劫 V2、夺舍或兽潮；只保留相应扩展接口；
- 禁止删除 legacy 战斗引擎，除非新引擎默认启用、全量验收通过且另行获得授权；
- 禁止覆盖脏工作树中的既有用户修改；
- 禁止提交失败测试、跳过迁移或仅凭类型定义宣称功能完成。

## 10. 执行与汇报要求

内置 AI 可以一次领取 P0-P7 全部范围，并按顺序自主实施，无需每阶段重复询问；但每个质量门失败时必须先修复，不得带病进入下一阶段。

最终汇报必须包含：

- 每阶段实际修改和未修改的范围；
- 数据迁移版本及旧档兼容结果；
- 测试、类型检查、生产构建与性能基准；
- 天机城垂直切片的逐步复现路径；
- 仍保留的 legacy 和明确删除条件；
- 与本方案不一致的地方、原因和影响；
- 未经授权没有实施的后续内容。
