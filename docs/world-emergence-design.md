# 修仙世界涌现叙事设计方案（无 AI 优先）

> 状态：草案，待评审
> 日期：2026-08-08
> 目标读者：后续实现者（含 AI 助手）——本文档是"防遗忘"的权威依据

## 1. 背景与设计目标

TaoSim 是纯文字修仙开放世界。在接入 LLM 之前，我们参照 WorldBox（无 AI 规则驱动涌现）与矮人要塞（Fortress 沉浸 / Legends 上帝双视角），让**世界仅靠规则自动演化出"像小说一样"的故事**。

目标：

1. 无 AI 前提下，世界自动演化出连贯、可回溯的故事（NPC 崛起/陨落、恩怨情仇、传奇生平）
2. 玩家既是世界一员（沉浸视角），又可切上帝视角查看世界全局（编年史）
3. 日志真实性：事件必须引用真实实体（NPC/地点/物品），不允许凭空捏造
4. AI 是增强层，不是依赖：后续 LLM 读取日志做对话/叙事增强，不改世界事实

## 1.1 参照对比与取舍（2026-08-09 调研）

> **借鉴边界（重要）**：向 WorldBox/矮人要塞等学习的是**状态机与系统架构**（需求→行为→状态变化→事件记录、双视角、因果链、成名正反馈），**具体机制细节一概不抄**——饥饿值、繁殖年龄、村庄占地、职业分工等沙盒参数在修仙世界里生硬且失真。一切机制须**修仙化、人情化**：NPC 是修士不是动物，驱动行为的是道途与牵挂，不是生理需求。

### 1.1.0 修仙人情化准则（机制映射表）

| 沙盒原型（不抄） | 修仙人情化替代 |
|---|---|
| 饥饿/幸福值驱动觅食 | **道途与牵挂驱动**：求道目标（境界瓶颈）、资源缺口（灵石/丹药/功法）、牵挂（道侣/师徒/挚友/仇敌）、寿元压力 |
| 繁殖（配偶→怀孕→幼年→成年） | **传承**（道侣双修→家族子嗣 / 收徒传道→衣钵相传）；子嗣以"世家子弟"出身出世，不收徒以"记名弟子"入门 |
| 村庄基建/职业分工 | 宗门经营（收徒/护山/出战/坊市）；NPC 的"职分"= 宗门内身份（弟子/长老/宗主）+ 道途方向（剑修/丹修/器修…） |
| 单位属性数值驱动战斗 | 恩怨/道义驱动（寻仇、报恩、护短、门户之争） |
| 所有细节地图可见可交互 | 双视角（§2.1）：沉浸视角只闻其名/听传闻，上帝视角查全貌——**保留修仙的神秘感** |

### 1.1.1 五款参照的取舍

| 参照 | 定位 | 借鉴 | 避免 |
|---|---|---|---|
| WorldBox | 无 AI 沙盒上帝模拟，NPC 自主行动/繁殖/交涉 | **需求驱动**（饥饿/幸福→行为，繁殖需饱食）、**代际链**（配偶→怀孕→幼年→成年）、**村庄基建**（建房/仓库/升级）、**职业分工**、所有单位地图可见可交互 | 纯沙盒无叙事层，故事靠玩家脑补（本方案已用事件日志补上） |
| 矮人要塞 | Fortress 沉浸 / Legends 上帝双视角 | 状态变化记录成日志→Legends 把日志重构成历史；**实体可信**（事件引用真实实体） | 深模拟产出大量无意义日志（谁喝了酒）→ 用 severity/visibility 分层裁剪（§3.1） |
| 了不起的修仙模拟器 | 题材对标 | 先天出身定起点（§7）、组织轨道（宗门→弟子→长老→宗主） | 无编年史回顾，玩家错过大部分世界故事；出生定命格标签（违背"先做到后成名"的因果，本方案已反转） |
| CK3 | 传奇/关系机制最成熟 | **声望数值化**（平滑中间量，优于"计数≥3"阶梯跳变）→ 建议 NpcRecord 增 `prestige`；关系/世仇/绰号/编年史全套 | 无上帝视角（本方案双视角更强） |
| RimWorld | 被排除 | — | Storyteller AI 本质是事件节奏控制，不是世界状态，与"无 AI"目标无关 |

### 1.1.2 涌现缺口诊断（对照 WorldBox，实测当前代码）

用户反馈"看不到任何 NPC、地图不直观、涌现不够好"。逐项对照后，**状态机不完善只是部分原因，更根本的是世界模拟与玩家地图双轨脱节**：

| # | 缺口 | 现状证据 | 修仙化目标（参照架构，不抄细节） | 影响 |
|---|---|---|---|---|
| G1 | 无道途/牵挂驱动 | 行为全是概率掷骰（云游 2% / 奇遇 0.4% / 突破判定），无动机 | 需求状态机：求道目标 / 资源缺口 / 牵挂 / 寿元压力 → 意向性行为 | 涌现像"随机事件"而非"自主行动" |
| G2 | 无传承/代际 | NPCGenerator 出生即成年（`age: 20+rand*100`），人口补充=凭空生成 | 传承链：道侣双修→子嗣 / 收徒→衣钵；子嗣以出身（世家/遗孤）定潜质 | 世界无"代际更替"与衣钵相传故事 |
| G3 | 无职分/宗门经营 | 无道途方向、无宗门事务经营 | 宗门职分（弟子/长老/宗主）× 道途方向（剑修/丹修/器修…）驱动宗门事件 | 无"社会结构"演化（远期） |
| G4 | 世界事件不咬合 NPC | 世界事件仅改 `worldTurmoil` 数值，不作用于任何 NPC | 天灾/异宝/量劫直接作用于牵涉 NPC（卷入、争夺、护短、寻仇） | 世界轨道与人物轨道平行 |
| G5 | 地图不可见 NPC | MapPanel 只渲染玩家；世界 NPC（state.npcs）无空间标记；遭遇 NPC 用 `Date.now()` 临时生成，**不在世界档案中** | 沉浸视角"闻其名不见其人"（传闻可见），上帝视角全貌可查 | 玩家"看不到 NPC"，涌现无感知——最直接原因 |

G5 补充：世界 NPC 存于 `WorldState.npcs`（locationId 指向 venue），而玩家地图是 hex 层——两个空间体系未打通；地图遭遇战另起炉灶用 `NPCGenerator.generate(tier, Date.now())`（非确定性、不持久化），等于存在**两套互不相干的 NPC 种群**。

### 1.1.3 对实施路线的影响（并入 §9）

- **批1a**：规则层保持数值化，但每项概率行为补"触发动机"注释，为 G1 铺路（不新增字段，先不改契约）。
- **批2 扩展**：G1 **道途/牵挂需求状态机**（求道目标 / 资源缺口 / 牵挂 / 寿元压力 → 意向性行为，替代纯概率掷骰）+ G4 世界事件↔NPC 咬合（异宝出世→邻近 NPC 卷入争夺→结仇/陨落→推高乱世指数；天灾→护短/寻仇/亡命）。
- **批2b 扩展**：G2 **传承链**（道侣双修→子嗣以"世家子弟"出世；长老收徒→衣钵相传），子嗣潜质由出身定，成长走现有修炼规则，**不做幼年形态模拟**（修仙重传承不重繁殖）。
- **批3 扩展**：G5 可视性——沉浸视角在地图/Venue 看到"在场者"名单与传闻（闻其名），上帝视角编年史/档案查全貌；遭遇统一从世界档案取 NPC（**禁用 Date.now()**）。
- **G3 职分/宗门经营** → 远期（版本 vNext），不在当前无 AI 涌现范围内。

### 1.1.4 验证结果（2026-08-09，种子 42/7/2026/314159/8888 全达标）

50 年模拟 × 5 种子质量评估器（`world-emergence-validation.test.ts`）——"95% 自信"操作化 = **所有种子 × 所有指标达标**：

| 指标 | 修订前基线 | 修订后 | 达标线 |
|---|---|---|---|
| 编年史规模（50 年） | 14166 | 900–1111 | ≤6000 |
| major/epoch 叙事占比 | 2% | 29–36% | ≥6% |
| 例行噪音占比（交易/出世/拜宗/云游） | 83% | 0% | ≤15% |
| 首次量劫年份 | 5 | 29–48 或全无 | ≥25 |
| 绰号授予（成名正反馈） | 1 | 12–19 | ≥2 |
| 遗府（死亡→机缘闭环） | 0 | 91–101 | ≥2 |
| 绝处逢生（命格豁免 N3） | 0 | 21–36 | ≥1 |
| 开局传奇存活 | 2/8 | 3–6/8 | ≥3 |
| 传奇人均事件 | 0–6 | 40–69 | ≥15 |

实施要点（N1–N4，已落地 engine + 测试，348 全绿）：
- **N1 事件流分层**：minor 例行事件只在实时流（`result.events`，沉浸细节），不入 `eventLog` 编年史；minor 不打断因果链（`pushNpcEvent` 跳过 `lastEventByNpc`）
- **N2 乱世指数平衡**：`TURMOIL_EVENT_DELTA` 12→5、灭门 10→4、宣战 6→2、战争结算 4→1、遗府登记 +5→+1（遗府暴增是 N4 的新爆点，已压）
- **N3 命格豁免**（新模板 `npc.escapedDeath`）：死劫判定 legendary 0.7 / prodigy 0.5 / talented 0.2 绝处逢生——寿元点延寿 10 载、仇杀点重伤替代陨落、战争点免死
- **N4 遗府闭环扩大**：仇杀陨落 / 战争战死的高境界（金丹+）亦 `registerHeritage`
- **N5 取名修仙化**（本轮）：百家姓前 64 姓 × 性别分库（男 40 / 女 40）共 5120 组合；世界内去重（重名换种子重取，除名时归还代际复用）——告别“10 姓 × 10 名”的张三李四乱感。抽样：韩归尘/范语嫣/昌婉清/俞芷若/姜观澜/卫昭雪
- 新增 `BigEventLog.templateKey`（编年史聚合 / 质量评估用，向后兼容）

意外的正向结果：seed 8888 纪元序列「乱世→大争→**太平**→乱世→大争→量劫」——世界有起伏循环而非直线冲爆（§2.2 世界轨道恢复力的体现）。

### 1.1.5 命格因果反转 + 实时演算（2026-08-09 轮）

**设计原则（用户）**："主角之所以是主角，正是因为他做到了、走出来了，所以他才是主角，而不是因为他是主角才做到这些"——天骄/传奇必须是**事后叙事标签（果）**，不能是出生预置的机制特权（因）。

落地（engine + UI + 测试，351 全绿，5 种子 × 9 指标全达标，浏览器实测通过）：
- **先天出身（因）**：`NpcDestiny.born`（mortal/fortune/reincarnated/inherited），出生掷 1%/0.5%/2.5%——只塑造起点（气运之子拔高 luck、大能转世 +6 悟性、逆天传承 +500 灵石），**不提供任何机制概率加成**
- **事迹认定（果）**：`NpcDestiny.tier` 出生一律 common；major 事件累计 ≥2 认定英才 / ≥5 天骄 / ≥9 传奇，升级产出 `npc.legend` 事件（"先做到，后成名"）——含预置强者：其传说是背景里"做到"的（epithet/生平保留），tier 仍从元年重新认定
- **删除命格机制特权**：tier 概率加成全部移除（突破 +0.1 / 奇遇 ×2 / 死劫豁免 odds 表）；`escapeDeath` 改面板因果（气运 luck×0.6 + 心性悟性×0.3）；师徒选人排序改 修为+悟性
- **实时演算（WorldBox 式）**：UI 层 `useWorld.setRealtimeSpeed(0/1/4/16)`，250ms tick 按日累积（1x = 1 世界日/秒），满 30 日 → `advanceTime(1,'World')` 结算；时钟显示"道历 X 年 X 月 第 X 日"；铁人自动存档实时模式跳过；离开游戏页自动停表

## 2. 核心概念

### 2.1 双视角（玩家感知模型）

| 视角 | 定义 | 可见范围 | 对应参照 |
|---|---|---|---|
| 沉浸视角 | 玩家是一个修士 | 亲身经历 + 周边传闻（信息不对称） | DF Fortress Mode |
| 上帝视角 | 世界编年史 | 全量事件，按年/月归档，重大事件提炼大事记 | DF Legends Mode |

数据只存一份全量事件流，视角 = 过滤规则（见 §6.3）。

### 2.2 涌现轨道（涌现的上限）

世界演化的"骨架"：每根轨道有明确阶段、跃迁门槛、跃迁代价。涌现故事 = 轨道交错。

| 轨道 | 阶段 | 跃迁 | 代价/张力 |
|---|---|---|---|
| 境界 | 炼气1-9→筑基→金丹→元婴→化神 | 突破（材料+资质+机缘） | 失败→重伤/寿元损耗 |
| 实力 | 功法/装备/法宝/斗法胜败 | 获得/被夺 | 生死、江湖地位 |
| 社会 | 散修→入宗→弟子→长老→宗主 | 声望/举荐 | 宗门恩怨、门户之见 |
| 关系 | 陌路→相识→好友/道侣/师徒→恩仇 | 事件沉淀，双向演化 | 背叛、复仇 |
| 世界 | 和平→乱世→大争→天道量劫 | 世界事件驱动 | 天灾、异宝出世 |
| 经济 | 灵石/资源积累 | 坊市/俸禄/机缘 | 破产、被劫 |
| 寿元 | 寿命硬约束 | 延寿/突破续命 | 与时间赛跑（修仙特色引擎） |

设计原则：**轨道交错产生故事**（突破缺资源→坊市→遇奇遇→结仇→寻仇→成名）。

**宗门权力轨道（让贤/夺位，2026-08-09 轮）**：社会轨道的顶端演化——宗主之位不再只靠陨落换班，权力有"主动交接"与"武力更迭"两条支线：

- **让贤（主动交班，非死亡驱动）**：寿元 >85% 的宗主每月萌生退意（退意概率 = `((寿元比-0.85)/0.15) × 0.2`，封顶 0.3，压力越大越笃定）；让贤后新宗主（修为最高长老）继位，旧主降为长老，事件 `social.sectAbdicate`。
- **夺位（野心驱动，真实斗法定胜负）**：仅 `seekFame` 志向的长老（野心驱动）且修为 tier ≥ 宗主时具备资格；每月 `USURP_CHANCE=0.15` 蓄势良久方一搏；一旦出手即真刀真枪（`sectPowerDuel`，与寻仇同源的真实面板结算，无敌人关系前置——夺位是权力野心而非仇怨）。胜者执掌宗门（旧主降为长老，性命仍在、宗门仍认其人，`social.sectUsurp`）；败者颜面扫地、被逐出宗门（factionId/socialRank 清空 + 成员除名，`social.sectUsurpFail`）。
- **数值验证（5 种子 × 50 年）**：夺位成功 3 次、夺位失败 2 次——权力轨道真实运转且非机制钦定（需野心+修为反超+蓄势掷骰+斗法全胜四重条件）；让贤 0 次属预期（传奇宗主寿元长，50 年窗口未到 85% 寿元线，机制由单元测试覆盖）。

### 2.3 规则交互

有趣来自系统之间咬合，不是事件数量。每个系统（突破/经济/关系/地图/奇遇）都改变世界状态，状态触发后续规则。

### 2.4 因果链

事件之间用 `relatedEventIds` 串联成"故事线"。例：突破失败 → 寿元迫近 → 寻机缘 → 破境 → 渡劫成功 → 名动一方。

### 2.5 叙事化（文字游戏的结构性优势）

- 事件描述 = 模板 + 真实实体变量（`{npc} 于 {location} 购得 {item}`）
- 传闻系统：重大事件按半径扩散成"江湖传闻"（沉浸视角的信息来源）
- 编年史/生平 = 日志的查询视图，不是预设

## 3. 数据模型

### 3.1 BigEventLog 扩展（contracts/event-log.ts）

```ts
interface BigEventLog {
  id: string;
  year: number;
  month: number;
  category: EventCategory;   // 现有 7 类 + 新增 crafting / breakthrough
  title: string;
  description: string;
  isMajorEvent: boolean;     // 兼容保留，逐步迁移到 severity
  involvedCharacterIds: string[];
  // ── 新增 ──
  locationId?: string;        // 真实地点引用
  severity: 'minor' | 'normal' | 'major' | 'epoch';
  visibility: 'local' | 'regional' | 'world';  // 传播半径 → 沉浸视角可见性
  source: 'engine' | 'player' | 'ai';
  narrative?: string;         // AI 文学化描述（增强层，不改事实）
  relatedEventIds?: string[]; // 因果链
}
```

### 3.2 NpcRecord（NPC 持久化档案，存于 WorldState.npcs）

```ts
interface NpcRecord {
  // 身份
  id: string;
  name: string;
  gender: 'Male' | 'Female';
  personalityId: string;
  origin: { type: '散修' | '世家' | '宗门' | '遗孤'; backgroundStoryId?: string };

  // 命格（气运之子）
  destiny: {
    tier: 'common' | 'talented' | 'prodigy' | 'legendary'; // 天骄≈prodigy，概率 ~0.3%
    luck: number;        // 加权奇遇/突破/死劫概率
    hidden: boolean;     // 前期不暴露，事件中逐渐显露
    epithet?: string;    // 江湖绰号（"云中仙"）
  };

  // 状态
  realm: RealmFullPath;
  soulState: SoulState;
  locationId?: string;
  factionId?: string;
  spiritRoot: SpiritRoot;
  attributes: { physique: number; comprehension: number; perception: number; agility: number; luck: number; charm: number };
  lifespan: { age: number; maxLifespan: number };
  skillIds: string[];

  // 出生与死亡（生平端点）
  birthYear: number;
  birthMonth: number;
  deathYear?: number;
  deathMonth?: number;
  causeOfDeath?: string;

  // 关系（事件沉淀型）
  relations: Record<string, RelationEntry>;

  // 生平（引擎聚合 + AI 增强）
  biography: {
    milestones: { eventId: string; year: number; month: number; title: string; realm: string }[];
    summary: string;    // 引擎一句话概览
    narrative?: string; // AI 文学化生平
  };

  lastUpdate: { year: number; month: number };
}

interface RelationEntry {
  type: 'master-disciple' | 'spouse' | 'dao-companion' | 'friend' | 'rival' | 'enemy' | 'clan' | 'benefactor' | 'debtor';
  bond: number;        // -100..100（爱恨）
  trust: number;       // 0..100
  events: string[];    // 关系事件链（结仇/报恩/倾心/背叛...）
  changedAt: { year: number; month: number };
}
```

### 3.3 世界状态扩展

```ts
interface WorldState {
  // ...现有字段
  npcs: Record<string, NpcRecord>;   // NPC 持久化档案
}
```

## 4. 月度 tick 规则集（无 AI 世界推进）

WorldEngine.step() 逐月执行（顺序固定，保证可复现）：

1. **修炼与突破**：每个 NPC 修为增长（灵根×悟性×季节）；境界跃迁判定——成功率 = 资质 × 资源 × 气运加权；失败→重伤/寿元损耗；成功且跨大境界→`major` 事件
2. **云游**：概率移动（目的地随机/投奔关系），更新 locationId
3. **社交相遇**：同地点 NPC 相遇→关系演化（初识/论道/交易/结仇）
4. **寻仇**：enemy 关系→概率触发斗法（胜负按实力轨道）
5. **奇遇**：气运加权触发（洞府/天材地宝/遗迹）；触发后状态变化（资源/实力/伤愈）
6. **坊市流动**：灵石交易、突破材料流转（与玩家经济同一套数据）
7. **寿元与坐化**：寿元尽→坐化（`major` 事件）→ 概率留下遗府（新奇遇源）
8. **传闻扩散**：`regional`/`world` 事件按半径向周边地区扩散
9. **人口补充**：NPC 低于阈值→`NPCGenerator.generate` 出世（复用 T3 成果）
10. **世界事件**：天灾/异宝出世/宗门大比/天道量劫倒计时

规则统一：**一切状态变化必须 emit 事件**（可测试约束）。

### 4.13 需求状态机（自主性 §4.13，2026-08-09 轮）

**对照 WorldBox 的核心缺口**：旧规则对所有人机械掷骰（概率涌现），NPC 没有"为什么做"的动机。需求状态机让 NPC 由**缺口驱动**：寿元 / 仇恨 / 孤独 / 道途 / 传承五类压力 → 志向（执念）→ 意向性行为（行为槽）。

**动机引擎**（`world-motivation.ts`，纯函数、可测试）：
- **缺口压力** `motivationPressuresOf(npc)`（0..1）：寿元=年龄/寿元比；仇恨=最恨之敌 bond 归一（-60 满压）；孤独=无道侣且年长（30 岁起积累）；道途=修为/阈值（卡关者高）；传承=寿元>85% 且无传人时非零
- **志向** `NpcAspiration`（7 种）：`seekDao / seekFame / seekLongevity / seekRevenge / seekPartner / seekSuccessor / wander`。初掷仅一次（心性池随机 + 寿元约束优先），此后**演化零 rng**（纯状态塑形：复仇得手→转求道；结道侣→转求道；有传人→了却心愿；寿元>90% 覆盖为求传人）
- **行为选择** `chooseBehavior` **零 rng**：深仇→`revenge`；求缘→`courtship`；传道→`teach`；求寿→`seekWonder`；扬名/逍遥→`wander`；求道卡关（dao≥0.8）→`seekWonder`，否则闭关

**行为槽执行**（step 循环按行为施加加成）：
- 闭关 `seclude`：修炼 focus×1.5（苦修蓄力）
- 访缘 `seekWonder`：奇遇机会 ×3
- 云游 `wander`：主动出行 35%（被动偶遇 2%）
- 寻仇 `revenge`：深仇者主动出手 25%（高于被动配对 10%），实力差距 ≤1 阶才出手，否则苦修蓄势

**代际链**（修仙人情化：以血脉与道统延续，非繁殖）：
- 求偶：孤独驱动的 `seekPartner` 寻觅道侣（异性、无主、年龄差≤40、同地优先）；**接受概率由双方魅力决定**（面板因果）
- 结道侣 `formCouple`：双向 `spouseId` + 关系沉淀 + 双修加成 1.15 + **志向转求道**（成家后专心道途）+ `social.couple` 事件
- 子嗣 `spawnChild`：双修 8 年冷却、2%/月；**子承父姓**（世界内去重）；出身世家（家学）；**灵根品级/元素/面板由父母继承**（资质由血脉决定，非机制特权）；`parentIds/childrenIds` 双向溯源；tier 仍从零认定（果）

**道统传承**（跨世代）：寿元将尽（>85%）且无传人者 → `seekSuccessor` → 慧眼收徒（悟性≥12、境界低于己、无师门）→ `passHeritage` 继承同一 `heritageLineId`（师祖→师→徒）→ 了却心愿转求道 → `heritage.pass` 事件。

**传奇执念**：预置传奇（玄都真人/血屠剑尊/凌霄子等）开局即带贴合人设的 `aspiration`——血屠寻仇、凌霄子扬名、求道者求道，老怪物的动机由生平写就，非随机。

**验证**：动机/代际/道统共 19 项新测试；5 种子 × 12 项指标全达标（新增：道侣 27-39 对、子嗣 125-155 人、道统传承 31-47 次）。

## 6. 双视角实现

### 6.1 沉浸视角（玩家）

可见 = 玩家直接参与（involvedCharacterIds 含玩家）OR（事件 location 在玩家当前地域 OR visibility=regional/world 且影响力够大）。

信息不对称产出：传闻（他人故事以"听说"口吻出现）、神秘感、被卷入感。

### 6.2 上帝视角（编年史）

全量事件按年/月归档；NPC 生平（按 involvedCharacterIds 反查 + NpcRecord.biography）；按地点/人物/类别检索。

### 6.3 过滤规则

```ts
function visibleToPlayer(event: BigEventLog, player: Character): boolean {
  if (event.involvedCharacterIds.includes(player.id)) return true;
  if (event.visibility === 'world' && event.severity >= 'major') return true;
  if (event.visibility === 'regional' && event.severity >= 'normal') return true;
  if (event.locationId && isNearby(event.locationId, player.locationId)) return true;
  return false;
}
```

## 7. 传奇涌现机制

1. **先天出身（因）**：出生掷出身（气运之子/大能转世/逆天传承/平凡），只调面板与初始条件（起点），不提供任何机制概率加成
2. **事迹认定（果）**：tier 出生一律 common；major 事件累计 ≥2 英才 / ≥5 天骄 / ≥9 传奇，升级产出 `npc.legend`——"先做到，后成名"
3. **面板因果**：luck 影响奇遇/突破/死劫（气运之子只是 luck 面板高）；绝处逢生由 气运+心性 决定，非命格特权
4. **成名正反馈**：major 事件积累 → 绰号（epithet）→ 更多关注 → 更"传奇"
5. **世界背景先行**：开局预生成若干强者简化生平（含宗门恩怨），世界一开局就有沉淀；强者的传说是背景里"做到"的（epithet 保留），tier 仍从元年重新认定
