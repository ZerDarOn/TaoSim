> 状态：架构蓝图 v1.1，已吸收契约层审计争议结论，待实施前评审  
> 日期：2026-08-10  
> 适用范围：世界演化、玩家人生、地图与时间、种族与社会、事实记录、AI 增强  
> 定位：后续重构与功能设计的上位约束；具体数值需通过原型和基准测试校准

### 本次修订冻结的结论

- `Character` 与 `NpcRecord` 不直接合并：前者是活动/战斗投影，后者是长期世界档案；二者共享稳定实体 ID 与领域规则，但不共享同一数据形状；
- 现有 `characterToNpcRecord` / `npcRecordToCharacter` 转换桥真实存在且已有调用，但属于有损投影工具，不能作为战后整体覆盖的通用归档器；
- 世界 NPC 进入玩家场景后，必须通过显式结果差量回写权威档案，禁止用战斗 `Character` 整体替换 `NpcRecord`；
- `activeNPCs` 当前含义不明，不能因字段存在就默认应持久化；先决定删除、重命名或升级为可恢复的活动场景快照；
- 战斗原子配置库不等于完整原子解释器；当前 UI 使用新旧战斗模块混合链路，必须先确定收敛目标；
- 第一条玩法垂直切片选择“带最小世界回写的渡劫”，兽潮保留为后续跨系统压力测试；
- 本轮只冻结方案与审计任务，不授权直接合并核心类型或大规模重写执行层。

## 1. 一句话定义

TaoSim 是一个**不依赖 AI 也能持续运行、所有人物与历史共享同一套事实的修仙世界模拟 RPG**；玩家是世界中的一个真实生命，AI 只扩展交流、叙事和行动表达，不替代世界规则。

核心关系：

```text
规则负责真实
世界制造经历
玩家参与历史
AI 扩展自由与表达
```

## 2. 产品目标

### 2.1 无 AI 时

游戏必须已经完整可玩：

- 世界在玩家不干预时持续演化；
- 玩家可能出生于凡人家庭、修仙世家、异族聚落、荒野或其他真实环境；
- 玩家不必一开始就是修士，能否踏入修仙取决于世界中的经历、资源与关系；
- 穿越、转世、夺舍等特殊开局可以跳过部分成长阶段，但仍落入真实时间、地点和身份；
- 玩家可以修炼、探索、交友、结仇、交易、战斗、加入或创建势力；
- NPC 与玩家遵守同一套核心规律，不存在仅为玩家服务的复制人和临时道具；
- 世界历史是状态变化后的事实记录，不是预先抽取的剧情卡。

### 2.2 接入 AI 后

AI 增加的是交互带宽，而不是世界真实性：

- 与真实 NPC 自由交谈；
- 根据 NPC 已知信息、性格、立场和记忆生成回应；
- 将自然语言解析为系统可验证的意图；
- 为战斗、环境、人物神态和历史提供丰富描述；
- 用已有事实生成书信、传闻、宗门公告、人物生平和编年史；
- 将复杂意图组合为规则内的多步行动，例如密谋、试探、欺骗、委托和谈判。

AI 不得直接决定突破、胜负、死亡、物品归属、关系变化或已经发生的历史。

### 2.3 非目标

- 不以堆积随机事件数量代替涌现；
- 不要求所有人口都进行逐帧完整模拟；
- 不把所有自由输入都解释成必定成功；
- 不让 AI 凭空创造权威事实；
- 不把种族简化成几个战斗数值加成；
- 不为了地图层级数量而增加没有尺度和职责的地图页面。

## 3. 当前项目现状

当前项目已经分别形成了多个可用原型，但还不是统一世界：

| 轨道 | 已有能力 | 主要问题 |
|---|---|---|
| 玩家 RPG | 创建角色、成长、装备、技能、炼丹炼器、战斗、旅行、事件选择 | 玩家状态和世界状态没有完全共用时间与实体 |
| 世界演化 | NPC 修炼、突破、关系、子嗣、师徒、宗门、经济、战争、编年史 | 月度巨型引擎，多处概率驱动，部分事件先果后因 |
| 地图 | 星界、大陆、20×20 大陆网格、场所、战斗地图 | 宏观与局部尺度混用，存在重复旅行模型，格子无真实距离 |
| 时间 | 玩家按天折算寿命，世界按月结算，UI 有临时日历，另有实时计时器 | 没有唯一权威时钟；玩家旅行时世界可能不动 |
| 内容事件 | 世界事件、奇遇卡、童年事件、日志模板 | 现象、行为、事实、文案都被称为 Event |
| AI | 上下文序列化、文案增强门面 | 尚无知识边界、记忆、意图解析和规则结算接缝 |
| 种族 | 人族式性别、年龄、婚配、子嗣和灵根继承 | 无统一种族、血脉、形态、栖息地、文化和族群关系模型 |

当前基础可以保留，但顶层组织方式需要调整。优先级应从“继续增加外围玩法”转为“统一时间、空间、实体、行为和事实”。

## 4. 总体设计原则

### 4.1 世界先于剧情

世界先发生状态变化，历史系统再记录事实，叙事层最后组织语言。

```text
状态与压力
→ 角色或组织形成意图
→ 行为验证
→ 规则结算
→ 原子提交状态变化
→ 生成不可变事实
→ 模板或 AI 生成表现
```

### 4.2 玩家与 NPC 同源

玩家可以拥有更精细的操作界面，但不拥有另一套物理、经济和社会规律。NPC 使用轻量或聚合结算时，结果也必须能映射回相同的领域事实。

“同源”指稳定身份、领域规则和权威事实同源，不要求所有实体常驻同一种完整内存结构。轻量档案、重点档案和战斗投影可以拥有不同字段，但必须明确：

- 哪个字段由哪一层权威持有；
- 哪些字段可确定性重建，哪些必须持久化；
- 升格和降格时哪些信息不得丢失；
- 临时投影只能通过经过验证的差量提交改变权威世界状态。

### 4.3 一个世界只有一个时间和一套实体

- 玩家旅行会推进世界；
- NPC 在地图上遇见玩家时必须来自世界档案；
- 拍卖中的物品必须有真实所有者；
- 战斗结果必须回写人物、地点、物品和关系；
- 世界中的地点 ID、势力 ID、人物 ID 和物品实例 ID 必须统一。

### 4.4 随机性作用于条件和结算，不直接宣布完整故事

可以随机灵脉波动、天气强度、行动意愿、命中和发现概率；不能直接随机“某宗门举行大比且某人获胜”并把它当作已发生事实。

### 4.5 分层模拟，不分裂事实

远处世界可以低频、聚合模拟；玩家附近可以高精度模拟。精度不同，但结果必须写入同一世界状态和事实账本。

## 5. 目标架构

```text
┌───────────────────────────────────────────────┐
│ 表现层：UI / 模板叙事 / AI 对话 / 编年史      │
├───────────────────────────────────────────────┤
│ 感知层：视野 / 情报 / 记忆 / 传闻 / 身份知识   │
├───────────────────────────────────────────────┤
│ 行为层：意图 / 命令 / 计划 / 验证 / 行动调度   │
├───────────────────────────────────────────────┤
│ 结算层：移动 / 社交 / 战斗 / 经济 / 组织 / 生态 │
├───────────────────────────────────────────────┤
│ 事实层：实体状态 / 所有权 / 关系 / 历史账本    │
├───────────────────────────────────────────────┤
│ 基础层：权威时钟 / 空间尺度 / 随机种子 / 索引  │
└───────────────────────────────────────────────┘
```

建议划分六个核心模块：

1. **World Clock**：唯一权威时间、时间推进和分层调度。
2. **Spatial World**：地图包含关系、物理尺度、位置、路径与空间索引。
3. **Entity & Society**：人物、种族、血脉、家庭、势力、文化与关系。
4. **Intent & Resolution**：意图、行为验证、规则结算和原子状态提交。
5. **Fact Ledger**：不可变事实、因果引用、所有权变化和历史查询。
6. **Perception & Narrative**：有限信息、传闻、编年史、模板和 AI 增强。

## 6. 统一时间系统

### 6.1 权威时钟

世界状态保存唯一绝对时间：

```text
WorldTime
- era / year / month / day
- hour / minute 或时辰
- elapsedMinutes
```

所有耗时行为只能通过统一入口推进：

- 行走两小时；
- 休息一夜；
- 炼丹三日；
- 飞舟航行十二日；
- 闭关六个月；
- 战斗十五分钟；
- 实时模式自然流逝。

实时模式、手动行动和快进不是三套时间逻辑，只是向同一时钟提交不同的时间增量。

### 6.2 分层调度

| 时间粒度 | 典型系统 |
|---|---|
| 分钟/时辰 | 战斗、对话现场、短效毒素、局部移动 |
| 每日 | 旅行、伤势、天气、商队、追踪、局部生态 |
| 每旬/每周 | 市场、宗门任务、治安、谣言传播 |
| 每月 | 修炼、人口、宗门经济、远方人物抽象行动 |
| 每年 | 代际、长期资源、历史归档、文化与族群变化 |

当时间跨过调度边界时执行相应系统，而不是每分钟遍历全世界。

### 6.3 时间不变量

- 世界时间只增不减；
- 同一动作不能重复推进时间；
- 玩家、NPC、市场和宗门读取同一个当前时间；
- 快进与逐步推进在同种子、同输入下产生等价结果；
- 存档必须包含权威时间和待执行的长期计划。

## 7. 多尺度地图与移动

### 7.1 地图层级

```text
世界/星界 World or Cosmos
└── 大陆 Continent
    └── 地域 Region
        └── 地区 Area            ← 当前缺失的关键层
            └── 场所 Venue
                └── 室内/战斗场景 Scene
```

| 层级 | 空间尺度 | 主要职责 |
|---|---|---|
| 世界/星界 | 星球、界域、星系 | 跨界关系、飞升、世界级灾变 |
| 大陆 | 大洲、海域 | 大势力、种族分布、跨地域路线 |
| 地域 | 州郡、山脉、荒原 | 领地、商路、军队、兽潮、人口与资源场 |
| 地区 | 山谷、森林、城郊、宗门山域 | 玩家探索、具体 NPC、采集、追踪、伏击 |
| 场所 | 百宝阁、客栈、大殿、洞府 | 所有者、库存、在场人物、设施和交互 |
| 场景 | 房间或战场 | 精细位置、遮挡、技能范围和临时环境 |

当前20×20大陆网格应优先重定义为地域层，而不是继续同时承担局部探索。

### 7.2 真实距离

每条边或地图格必须具有物理尺度，不能直接把地形成本当成天数。

```text
pathDistance = Σ segmentDistance

effectiveSpeed =
  baseSpeed
  × movementMode
  × cultivationModifier
  × techniqueOrMount
  × roadModifier
  × terrainModifier
  × weatherModifier
  × injuryModifier
  × loadModifier
  × partyModifier

travelDuration = pathDistance / effectiveSpeed
```

移动方式包括步行、骑乘、轻身术、御剑、遁术、飞舟和传送。高境界修士带领凡人商队时，队伍速度仍受最慢成员和运输方式限制。

### 7.3 战斗地图

战斗场景是当前地区或场所的高精度投影，不是脱离世界的副本：

- 继承地形、天气、时刻和附近单位；
- 逃跑方向映射回原地区；
- 尸体、掉落、破坏和目击者回写世界；
- 战斗耗时推进权威时钟；
- 增援是否到达取决于真实距离和速度。

## 8. 分层世界演化

### 8.1 模拟精度

| 层级 | 对象 | 模拟方式 |
|---|---|---|
| 聚合人口 | 大量凡人、低阶生灵、基础妖兽种群 | 地区计数、出生死亡率、迁徙和资源压力；不强制拥有逐个实体 ID |
| 轻量档案 | 普通修士、商队、基层成员 | 稳定 ID、精简档案、计划状态、低频结算 |
| 重点档案 | 宗主、天骄、仇敌、独特物品持有者、重大参与者 | 持久关系、资产、记忆、目标和更细粒度行为 |
| 活动现场投影 | 当前地区、场所、对话和战斗参与者 | 高频位置与行动结算；属于运行时上下文，不是第四种永久档案 |

持久化精度可以升格或降格，现场投影则按场景创建和释放。升降格不得只由距离阈值决定，而应使用“升格原因 + 相关度评分 + 迟滞”机制：

- 获得姓名、灵根、职位、稳定关系、独特物品、长期计划或参与重要事实时，形成不可立即取消的升格原因；
- 玩家关系、组织职位、独特资产、活跃计划、近期事实和空间接近共同形成相关度，空间距离只是其中一项；
- 升格使用较高阈值，降格使用较低阈值，并要求连续多个调度周期低于阈值，避免快速移动造成反复抖动；
- 战斗、交易、追踪、承诺和未完成计划期间禁止降格；
- 降格必须保留稳定 ID、权威关系、所有权、重要事实、长期计划和可复现种子。

### 8.2 演化目的

自动演化不是为了制造日志数量，而是保证：

- 玩家遇到的人已有过去和关系；
- 商品、功法和法宝有来源；
- 势力冲突有资源、领地和历史原因；
- 灾难能真实伤害人物与社会；
- 玩家离开一个地方后，那里仍会发生变化；
- 玩家死亡后，世界和其留下的关系继续存在。

## 9. 种族、血脉与族群社会

### 9.1 概念必须分离

修仙世界中以下概念不能合并成一个 `race` 枚举：

| 概念 | 含义 | 示例 |
|---|---|---|
| 生物种族 Species | 基础生命形态与生理规则 | 人族、狐族、羽族、鳞族、草木灵族 |
| 血脉 Lineage | 家族或祖源传承 | 青丘血脉、真龙旁系、上古神木血脉 |
| 当前形态 Form | 当前肉身和外显状态 | 原形、化形、半化形、鬼体、夺舍之身 |
| 文化 Culture | 价值观、礼法、语言和制度 | 人族宗门文化、妖庭文化、山野部族文化 |
| 势力 Faction | 实际政治组织 | 宗门、王朝、妖庭、族群部落、商会 |
| 修炼道路 Path | 修行方法和力量来源 | 道修、剑修、体修、妖修、鬼修、魔修 |
| 阵营/立场 Alignment | 当前政治与道德立场 | 正道联盟、中立、敌对、附庸 |

“魔修”通常首先是一条修炼道路或社会身份，不应自动等同于生物种族；“妖族”也不应是单一生物模板，而应包含大量物种、血脉和文化。

### 9.2 种族定义

每个种族至少描述：

- 生命周期：出生、幼年、成熟、衰老、自然寿命；
- 身体结构：体型、感官、器官、可装备部位；
- 栖息需求：温度、灵气属性、水域、阴气、地形；
- 移动方式：步行、飞行、游水、遁地或特殊形态；
- 修炼入口：灵根、血脉觉醒、吞吐日月、香火、阴气等；
- 形态阶段：开智、化形、蜕变、鬼体凝实等；
- 繁衍与传承：生育、孢种、分株、魂体转化、收徒或族群孵化；
- 天赋与代价：优势必须伴随生态、资源、社会或成长约束；
- 语言与感知：是否能与其他种族直接交流、是否能识别气息；
- 社会接受度：由地区文化和历史决定，而不是全世界固定。

### 9.3 血脉与形态变化

血脉独立于种族，允许：

- 返祖和血脉觉醒；
- 混合血脉及兼容性；
- 化形与半化形；
- 夺舍导致灵魂与肉身种族不同；
- 转世保留部分灵魂印记但更换种族；
- 尸解、鬼化、魔染等后天形态变化；
- 血脉被提炼、移植、封印或污染。

角色因此至少需要区分“灵魂身份”和“当前肉身”。NPC 识别到的可能只是外显形态，真实血脉可以成为秘密和剧情来源。

### 9.4 种族关系如何产生

种族冲突不能只靠固定的“人族讨厌妖族 -30”。冲突应主要来自：

- 栖息地与灵脉争夺；
- 捕食、采药、猎妖和材料需求；
- 历史战争、屠杀、奴役和盟约；
- 宗教、文化和修炼道路差异；
- 王朝法律、宗门政策和贸易限制；
- 谣言、宣传和重大人物行为；
- 语言隔阂与信息不对称；
- 个体关系对群体印象的反向影响。

建议关系分三层：

```text
个体关系：某个人对另一个人的信任、感情和仇恨
组织关系：宗门、部族、妖庭、王朝之间的外交
族群态度：某地区文化对某种族的长期认知和制度待遇
```

三层互相影响但不互相覆盖。即使两族交战，个体仍可能是挚友、道侣、师徒或恩人；个体背叛也可能被宣传为族群仇恨的证据。

### 9.5 种族与世界生态

种族必须占据真实生态位：

- 妖兽种群受食物、灵气、领地和天敌影响；
- 开智个体从种群层升格为角色；
- 化形妖修可能加入宗门、妖庭或独自修行；
- 草木灵族与灵脉、季节和采集行为相关；
- 鬼族或阴魂受战场、墓地、阴脉和超度行为影响；
- 大规模猎杀、战争或资源开采会改变种群分布。

兽潮由生态压力、妖王驱使、领地破坏或灾变产生，不由“抽中兽潮事件”直接产生。

## 10. 玩家人生与开局

### 10.1 普通出生

```text
世界选择真实父母或抚养环境
→ 出生为婴幼儿
→ 家庭、地区和种族决定早期可接触资源
→ 成长、学习、劳动、迁徙和关系自然发生
→ 因测灵、救助、灾难、收徒、遗物等实际情况接触修仙
→ 可能拜入仙门，也可能走散修、妖修、鬼修或凡人人生
```

童年不再按年龄播放固定剧情。年龄只解锁能力，具体经历由家庭、地点、人物和世界状态产生。

### 10.2 特殊开局

- 穿越：获得有限前世认知，直接进入某个真实身份和地点；
- 转世：可能保留模糊记忆、因果或灵魂特质；
- 夺舍：灵魂与肉身不一致，并承担身份暴露和融合风险；
- 化形：从异族成长阶段进入人形社会；
- 遗孤：父母死亡必须能在世界历史中追溯；
- 大能重修：保留认知但失去原有力量、资源和社会控制力。

特殊开局改变起点，不授予脱离规则的剧情特权。

## 11. 社交、阴谋与关系

背叛、情变、下毒、暗算、复仇和友谊都不应是独立事件卡，而应由共享系统形成。

### 11.1 关系状态

- 感情与亲密；
- 信任；
- 欲望与吸引；
- 利益依赖；
- 恐惧；
- 尊重；
- 嫉妒；
- 公开身份与秘密关系；
- 共同经历和承诺；
- 对背叛、欺骗和伤害的记忆。

### 11.2 秘密与信息

阴谋成立需要：

- 行动者知道目标和机会；
- 有实际工具、毒物、金钱或协作者；
- 存在接近目标的空间路径；
- 目击者、证据和调查可以产生；
- NPC 只能依据自己知道的信息行动；
- 谣言可能失真，但事实账本保持真实。

### 11.3 行为链示例：下毒

```text
形成杀意
→ 搜集或购买毒物
→ 观察目标习惯
→ 获取接近饮食/丹药的机会
→ 投毒与隐蔽检定
→ 毒性、体质和解毒结算
→ 症状、诊断、证据和嫌疑出现
→ 调查、追责、报复或误判
```

## 12. 真实经济、交易与拍卖

百宝阁和拍卖行使用真实所有权与稀缺性：

- 每件重要物品拥有唯一实例、来源和当前所有者；
- 委托人、底价、期限、保密要求和佣金真实存在；
- NPC 根据需求、财富、情报、性格和关系参与竞价；
- 灵石在买家、卖家、拍卖行和税收之间真实转移；
- 商品运输、仓储和失窃都具有空间位置；
- 串标、抬价、借贷和欺诈是可执行行为；
- 杀人夺宝会产生尸体、赃物、目击、仇恨、悬赏和宗门追责；
- 赃物可能被识别、洗白、转卖或追踪。

市场不是定期刷新出来的无主商品列表，而是世界生产、探索、死亡、交易和掠夺的结果。

## 13. 灾难、兽潮与势力战争

### 13.1 灾难

灾难由世界条件触发并影响真实区域：

- 灵气或地脉变化；
- 天气和地质异常；
- 妖兽生态失衡；
- 阵法、秘境或大能行为；
- 资源过度开采；
- 世界纪元与量劫压力。

灾难需要实际作用于人口、地点、建筑、资源、交通和人物，而不是只修改一个“乱世指数”。

### 13.2 势力战争

战争来自：

- 领地和灵脉；
- 商路与税收；
- 旧怨、盟约和继承；
- 种族或文化政策；
- 关键人物野心与误判；
- 对灾难和资源短缺的不同应对。

宣战只是行动，不是战争结果。军队或修士必须移动、补给、侦察和交战；领地变化来自真实结算。

## 14. 行为、事实与事件的边界

### 14.1 四种数据必须分开

| 类型 | 时态 | 示例 |
|---|---|---|
| Intent / Command | 将要尝试 | 某长老打算夺位 |
| Resolution | 正在结算 | 校验资格并进行真实斗法 |
| Fact | 已经发生 | 长老获胜、旧宗主退位、职位转移 |
| Narrative | 如何描述 | “某某于宗门大比中夺位成功” |

### 14.2 允许的内容库

- 规则库：描述世界规律；
- 行为库：描述角色和组织可尝试的动作；
- 表现模板库：描述事实如何显示；
- 局部场景库：用于手工设计的玩家局部互动，但不得伪装成世界已经自然演化出的历史。

### 14.3 事实账本

事实至少记录：

- 时间和地点；
- 参与实体；
- 行为与结果；
- 重要状态变化；
- 物品和资源转移；
- 前置事实或原因；
- 可见性与目击者；
- 是否为公开事实、秘密或传闻来源。

事实账本是编年史、人物生平、宗门历史、传闻和 AI 知识检索的共同来源。

## 15. AI 集成边界

### 15.1 NPC 对话

AI 输入必须经过知识裁剪，只包含：

- NPC 的性格、文化、立场和当前情绪；
- NPC 亲眼见过、被告知或推断出的信息；
- 与玩家的共同经历和承诺；
- 当前地点可感知状态；
- 本次对话目标和允许的行为接口。

NPC 不能凭借 AI 全知世界。

### 15.2 开放行动

```text
自然语言
→ 意图解析
→ 拆分为规则动作或多步计划
→ 权限、资源、距离和可行性校验
→ 世界结算
→ 事实提交
→ AI 描述结果
```

若玩家提出系统暂不支持的行为，AI 应：

1. 映射到已有动作组合；或
2. 返回缺少的条件；或
3. 明确说明当前无法执行。

不得通过修改文案假装行为已经成功。

### 15.3 AI 降级

AI 不可用时：

- 行为和世界继续运行；
- 对话使用有限模板或选项；
- 战斗和历史使用结构化描述；
- 存档不依赖模型上下文；
- AI 生成内容不成为唯一事实来源。

## 16. 关键架构决策

### ADR-1：唯一权威时间

- **Decision**：玩家、世界、地图和实时模式共用一个持久化世界时钟。
- **Context**：当前玩家按天、世界按月、UI 日历和实时计时器彼此分离。
- **Options**：继续多时钟同步；统一为绝对时间；仅保留月度回合。
- **Chosen**：绝对时间 + 分层调度。
- **Tradeoff**：需要迁移多个入口，但能保证旅行、闭关和世界演化一致。
- **Rollback**：保留月度世界结算适配器，迁移期间由统一时钟触发旧月度引擎。

### ADR-2：增加地区层并赋予真实尺度

- **Decision**：将当前大陆20×20网格定位为地域层，新增地区层承担局部探索。
- **Context**：当前一格同时代表长途距离和地面级遭遇，尺度自相矛盾。
- **Options**：扩大现有单层网格；只用节点图；多尺度地图。
- **Chosen**：多尺度地图，场景按需生成或加载。
- **Tradeoff**：地图切换和位置映射更复杂，但宏观演化与局部探索可以同时成立。
- **Rollback**：初期只为一个地域实现地区层，其余地点继续使用旧场所页面。

### ADR-3：事实驱动叙事

- **Decision**：事件日志只能由已提交状态变化生成。
- **Context**：当前部分世界事件和奇遇先抽文案，再补状态后果。
- **Options**：事件卡驱动；状态差异自动推导；结算器显式返回事实。
- **Chosen**：结算器显式返回结构化事实，叙事层消费事实。
- **Tradeoff**：需要重构事件类型，但能保证历史可信、可查询和可供 AI 使用。
- **Rollback**：手工奇遇暂保留为局部场景，不进入权威世界史，逐步迁移。

### ADR-4：种族、血脉、文化、势力和道路分离

- **Decision**：不使用单一 race 字段承载所有差异。
- **Context**：修仙题材存在化形、夺舍、混血、转世、文化迁移和修炼道路转换。
- **Options**：单枚举；标签集合；分领域模型。
- **Chosen**：分领域模型，角色组合引用。
- **Tradeoff**：数据结构更复杂，但避免后续规则冲突和硬编码。
- **Rollback**：首批仅实现人族和一个非人族样板，其他内容通过默认策略兼容。

### ADR-5：分层模拟

- **Decision**：人口计数、轻量实体、重点实体和活动现场使用不同精度。
- **Context**：完整逐人月度扫描无法扩展到大规模世界。
- **Options**：全部完整模拟；全部统计模拟；按关注度分层。
- **Chosen**：分层并支持升降格。
- **Tradeoff**：需要定义升降格不变量，但可以兼顾规模与个人历史。
- **Rollback**：在升降格成熟前，只启用氛围人口和完整 NPC 两层。

### ADR-6：权威档案与活动投影分离

- **Decision**：保留 `NpcRecord` 与 `Character` 的职责分离，不合并为巨型角色类型；稳定实体 ID 和权威领域状态跨层共享。
- **Context**：`NpcRecord` 承担长期世界演化，`Character` 承担玩家、交互和战斗所需的高精度状态。直接合并会让大量 NPC 常驻背包、行动点和战斗瞬态；完全割裂又会让玩家遭遇不到真实世界人物。
- **Options**：合并为单一完整类型；维持互不关联的双类型；权威档案 + 按需投影。
- **Chosen**：权威档案 + 按需投影，并在字段权威表中声明每个字段的所有者、重建规则和生命周期。
- **Tradeoff**：需要维护投影边界和差量协议，但能兼顾大规模模拟、数据一致性和现场玩法。
- **Rollback**：迁移期保留现有 mapper，只允许用于已验证场景；未定义权威归属的字段禁止自动回写。

### ADR-7：战斗与现场行为使用差量结算

- **Decision**：活动投影不得整体覆盖世界档案；结算器返回经过验证的 `OutcomeDelta`，由世界事务统一提交。
- **Context**：现有转换会默认或重建出生年月、出身、命格、地点、生平、气血、灵力和背包。把战斗 `Character` 整体归档可能抹除 NPC 的长期历史。
- **Options**：整体对象回写；字段白名单复制；结构化结果差量。
- **Chosen**：结构化差量，至少区分生命/伤势、修为、位置、所有权、关系和事实记录，并对同一实体版本做冲突校验。
- **Tradeoff**：每类结算需要明确结果契约，但避免无关字段被覆盖，并支持审计、回放和存档恢复。
- **Rollback**：首批只允许渡劫和一对一战斗提交最小差量，其余旧玩法继续走原路径但不得覆盖 `NpcRecord`。

### ADR-8：运行时缓存不默认进入存档

- **Decision**：重新审查 `activeNPCs`；可由权威档案确定性重建的展开态不持久化，需要断点恢复的状态改为明确的活动场景、战斗或交易快照。
- **Context**：当前 `activeNPCs: Record<string, Character>` 固定保存为空对象，无法表达它是缓存、权威数据还是进行中事务。
- **Options**：继续保存完整活动 NPC；删除字段；拆分为可恢复运行时场景。
- **Chosen**：契约审计后删除或迁移该字段；只有无法重建且必须跨存档恢复的进行中状态才进入专用快照。
- **Tradeoff**：需要存档迁移，但可避免重复权威数据、存档膨胀和读档冲突。
- **Rollback**：旧存档继续接受该字段但忽略其内容，直到新场景快照格式稳定。

### ADR-9：战斗引擎先收敛，再扩展原子

- **Decision**：渡劫和新技能执行前，先选择唯一目标战斗运行时，并制定旧 `combat/` 与新 `battle/` 的迁移边界。
- **Context**：当前 UI 使用旧 `CombatEngine` 管理行动，同时调用新伤害和射程辅助函数；新 `BattleEngine` 尚无 `UseSkill` 命令，普攻仍使用固定伤害规格。原子注册表中的配置不代表运行时已经能够解释。
- **Options**：长期维持混合链路；回退旧引擎；补齐新引擎并逐步迁移 UI。
- **Chosen**：在契约审计中依据确定性、命令模型、技能原子支持和 UI 迁移成本做一次明确 ADR；结论产生前不在两套引擎上重复实现渡劫。
- **Tradeoff**：短期推迟玩法功能，但避免第三套战斗路径和重复返工。
- **Rollback**：保留旧 UI 适配层，按单个行为迁移，并用同场景对照测试验证结果。

### ADR-10：功法与战斗技能分域，预算由基准反推

- **Decision**：招式/术法、功法、神通和秘术不共用一套未经校准的战斗原子预算。
- **Context**：战斗原子主要描述射程、数值、状态、时间和地形；功法还会影响修炼速度、经脉负担、突破、寿命和资源经济。仅凭境界分与材料纯度无法证明平衡。
- **Options**：统一静态加法预算；各内容硬编码；分域原子 + 基准场景校准。
- **Chosen**：先定义各境界目标行动经济、参考技能和可接受强度包络，再用组合合法性、非线性交互、循环检测和确定性仿真校准预算与反噬。
- **Tradeoff**：需要建立基准技能与仿真场景，但 AI/MOD 自创内容才具备可验证的平衡边界。
- **Rollback**：校准完成前，自创内容只生成草案，不进入权威存档或正式战斗。

### ADR-11：首个垂直切片采用带最小世界回写的渡劫

- **Decision**：第一条端到端玩法切片选择渡劫，不选择兽潮；首版验收必须包含最小世界事务。
- **Context**：兽潮能覆盖生态、人口、势力、移动和战斗，但依赖面过大。纯战斗渡劫又会成为玩法孤岛。
- **Options**：兽潮综合切片；纯战斗渡劫；带最小世界回写的渡劫。
- **Chosen**：渡劫首版至少提交权威耗时、地点、参与实体、境界/伤势/寿命/死亡差量和一条结构化事实；观劫者、地形破坏、天气和势力反应后续扩展。
- **Tradeoff**：首版表现范围受限，但能以较小依赖面验证时间、空间、实体投影、战斗和事实链。
- **Rollback**：若目标战斗引擎尚未收敛，只实现结算契约与测试桩，不创建独立渡劫引擎。

## 17. 领域风险

### 不变量

- 人物、地点、势力、物品和事实引用必须有效；
- 同一重要物品只有一个当前所有者；
- 人物只能处于一个确定位置或一条确定旅行路径；
- 灵魂、肉身、种族与形态变化可追溯；
- 日志不得声明未实际发生的事实。

### 原子性

- 交易、拍卖、战利品、死亡、继任、夺位、结缘和传送必须全有或全无；
- 战斗提交必须同时更新人物状态、物品、位置、关系和事实；
- 失败时不能留下重复扣款、幽灵物品或半转移职位。

### 并发

- 实时流逝、玩家操作、自动存档和 AI 请求不能并发改写权威状态；
- 同一物品不能被两个买家同时买走；
- 同一 NPC 不能同时执行互斥计划。

### 副作用

- 存档、AI 调用和 UI 动画不得先于状态提交成为事实；
- AI 超时不能阻塞世界演化；
- 可逆的展示失败不能回滚已经正确提交的世界事实。

### 信任边界

- AI 输出、MOD 内容、存档输入和玩家自然语言均需验证；
- AI 只能提交允许的意图，不能直接写状态；
- MOD 规则必须声明读写范围和确定性要求。

### 可观测性

至少统计：

- 各粒度调度耗时；
- 活跃实体、轻量实体和人口计数；
- 升格、降格和索引命中；
- 每类行为尝试、失败原因和成功率；
- 每月事实数量与叙事数量；
- 悬空引用、重复所有权和时间漂移；
- AI 降级率、事实校验失败和知识越权。

### 性能

- 避免每个规则独立扫描全世界；
- 维护地点、势力、关系、种族、计划和活动实体索引；
- 远方实体按调度边界批处理；
- 事实账本按时间、实体和地点建立查询索引；
- 以500、2000、10000重点实体的百年模拟作为基准。

## 18. 建设顺序

### Phase 0：契约审计与决策冻结（只审计，不重构）

- 绘制 `WorldState.npcs → NpcRecord → Character → BattleState → SavePayload` 的真实调用与数据流；
- 为核心字段标注权威来源、投影方式、可重建性、允许丢失范围和写回责任；
- 核实 mapper 当前所有调用、测试和有损行为，禁止以名称搜索代替类型关系与调用图追踪；
- 决定 `activeNPCs` 删除、迁移或转为活动场景快照；
- 明确世界 NPC 进入 UI 遭遇、战斗结算和回写的缺口；
- 完成双战斗引擎收敛 ADR；
- 固定 Intent、Resolution、Fact、Narrative、OutcomeDelta 与 RuntimeSnapshot 术语；
- 输出迁移顺序、兼容策略、回滚点和回归测试清单，经评审后才能进入 Phase 1。

### Phase 1：最小世界底座

- 建立持久化世界时钟和统一推进入口；
- 建立稳定实体引用、结构化事实和结果差量契约；
- 建立最小空间位置引用和场景来源；
- 为状态提交定义原子事务、版本校验和重复执行保护；
- 保留旧月度引擎与旧战斗 UI 作为受控适配器。

### Phase 2：实体投影与遭遇闭环

- 明确 `NpcRecord` 的长期权威字段；
- 将现有 mapper 收窄为命名明确的场景投影，禁止通用整体回写；
- 实现世界 NPC 按需进入对话或战斗现场；
- 实现 `OutcomeDelta` 校验、提交、事实生成和存档恢复；
- 删除临时生成后丢弃、无法追溯来源的世界人物路径。

### Phase 3：渡劫垂直切片

- 在选定的目标战斗引擎中实现最小渡劫命令与确定性结算；
- 接入权威时间、地点和实体投影；
- 回写境界、伤势、寿命、死亡等最小结果差量；
- 生成可查询、可叙事、可读档恢复的渡劫事实；
- 第二步再加入观劫者、地形破坏、天气与势力反应。

### Phase 4：统一空间与移动

- 清理重复旅行模型；
- 明确大陆、地域、地区和场所包含关系；
- 为路径和格子赋予物理距离；
- 引入速度、移动方式、地形和队伍公式；
- 让世界 NPC 与玩家地图使用同一位置体系。

### Phase 5：种族与生命周期样板

- 先实现人族与一个非人族样板；
- 建立种族、血脉、肉身、灵魂和形态变化；
- 支持出生、成长、开智或化形、衰老和死亡；
- 建立族群态度、栖息地和势力关系；
- 验证跨种族个体关系和冲突不是固定剧本。

### Phase 6：行为、组织与人生闭环

- 将动机转为可验证意图；
- 实现家庭、宗门、商会、部族和妖庭的组织行为；
- 实现资源、领地、招募、继任、外交和战争；
- 将随机世界事件迁移为世界条件与行动结果；
- 完整出生、成长、社交、秘密、毒素、调查、交易与追责；
- 用兽潮验证生态、移动、人口、势力、战斗和经济的跨系统一致性。

### Phase 7：AI 增强

- 有限知识对话；
- NPC 记忆与关系上下文；
- 自然语言意图解析；
- 多步计划提案与规则验证；
- 战斗、环境、历史和人物叙事增强；
- AI 关闭时完整降级。

## 19. 第一阶段微计划：契约层审计 v2

### Task 1：真实数据流与调用图

- 输入：`Character`、`NpcRecord`、战斗状态、`WorldState`、`SavePayload` 及其实际调用点；
- 输出：从生成、持久化、展开、交互、战斗、结算到读档的实体数据流图，并标出断点和旁路；
- 风险：再次因搜索词不完整误判能力不存在；
- 回滚：纯文档任务，无运行时变更；
- 边界：必须按类型引用、导入导出和调用链交叉验证。

### Task 2：字段权威矩阵

- 输入：核心类型全部字段和 mapper 行为；
- 输出：字段的权威持有者、投影来源、可重建性、持久化要求、写回权限和丢失后果；
- 风险：双向转换覆盖出生、身世、位置、生平、库存或现场状态；
- 回滚：纯文档任务；结论未评审前不改类型。

### Task 3：投影与差量不变量

- 输入：现有 mapper、战斗结果和世界状态修改入口；
- 输出：`expandForScene`、`OutcomeDelta`、`applyOutcome` 的职责边界及重复提交、版本冲突、失败回滚规则；
- 风险：部分提交、重复掉落、状态回满、历史被覆盖；
- 回滚：先以接口草案和测试用例表达，不替换现有实现。

### Task 4：运行时状态与存档边界

- 输入：`activeNPCs`、战斗、交易、对话、旅行和长期计划的恢复需求；
- 输出：删除/迁移 `activeNPCs` 的正式决定，以及 `activeScenes`、`activeBattles`、`pendingTransactions` 是否必要；
- 风险：保存重复权威数据，或读档后丢失无法重建的进行中事务；
- 回滚：保留旧字段读取兼容，停止新增写入。

### Task 5：双战斗引擎收敛审计

- 输入：旧 `combat/`、新 `battle/`、UI 调用链、技能原子消费点和测试；
- 输出：唯一目标引擎、保留能力、缺失命令、迁移顺序、适配层和删除条件；
- 风险：渡劫或技能在两套引擎重复实现，继续扩大混合链路；
- 回滚：审计期间维持当前 UI 行为，不添加第三条执行路径。

### Task 6：迁移与验收计划

- 输入：前五项审计结论；
- 输出：按依赖排序的实现任务、测试对、存档迁移、观测点、回滚点和渡劫切片验收清单；
- 风险：先改类型后发现权威边界错误，导致二次迁移；
- 回滚：未经评审不进入实现阶段。

第一阶段共 6 项任务。Task 1 与现状取证先行；Task 2—5 基于同一份调用图推进；Task 6 最后汇总。审计完成后必须再次评审，不能自动进入代码实施。

## 20. 验收标准

在开始大规模 AI 集成前，至少满足：

1. 玩家连续旅行60天，世界中的 NPC、市场和宗门同步过去60天；
2. 同一路程因境界、道路、坐骑、天气和负重不同而耗时不同；
3. 地图遇见的 NPC 必须来自 `WorldState` 中的稳定实体，能按需展开为现场投影，并在结算后以差量回写原档案；
4. 一次拍卖能追溯物品来源、竞拍者、资金转移和最终所有者；
5. 一场战争能追溯冲突原因、参与势力、移动、战斗、伤亡和领地变化；
6. 一个兽潮由生态或势力原因形成，并真实影响地区人口和人物；
7. 至少两种生命形态遵守不同生命周期和生态规则，同时允许个体跨族友谊或敌对；
8. 编年史中的每个实体和结果都能回查到真实状态或已归档事实；
9. 关闭 AI 后所有规则、存档、世界演化和核心 RPG 体验仍然可用；
10. AI 生成的对话不能泄露 NPC 不知道的事实，也不能直接修改世界；
11. `Character → NpcRecord → Character` 的测试必须区分“允许重建的投影”与“必须保持的权威字段”，不得把有损转换误称为无损 round-trip；
12. 存档中不存在含义不明的活动 NPC 副本；所有持久化运行时快照都能说明为何不可重建及如何恢复；
13. 新增技能和渡劫只运行于选定的目标战斗引擎，UI 不再长期混用两套相互不完整的执行语义；
14. 第一版渡劫能从真实人物和地点进入战斗，推进权威时间，提交境界/伤势/寿命/死亡结果，并生成一条可查询事实；
15. 同一渡劫结果在提交失败、重复提交或读档恢复时，不会重复突破、重复死亡或重复生成奖励与事实。

## 21. 需要后续校准的假设

- 地域格和地区格的具体物理尺寸；
- 世界基础时间粒度采用分钟、刻还是时辰；
- 首批种族样板选择狐族、草木灵族或其他类型；
- 远方轻量实体的最低结算频率；
- 玩家是否始终可以切换上帝视角，以及该视角是否影响沉浸模式的信息限制；
- MOD 是否允许添加规则代码，还是仅允许数据化内容；
- 单机首发目标的重点实体规模与百年快进性能预算。

这些数值和内容选择可以调整，但不得破坏本文确立的五个核心不变量：

1. 一个权威时间；
2. 一套稳定实体身份与权威事实，允许多种精度投影；
3. 有尺度的空间；
4. 先结算事实、后生成叙事；
5. AI 增强世界，不替代世界。
