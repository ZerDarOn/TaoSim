# 大世界地图与持续涌现重构草案

> 状态：已由 [动态空间与可观察世界完整重构方案](dynamic-spatial-world-implementation-plan.md) 替代；本文仅保留早期问题记录与止血方案。

> 目标：保留非像素化的视觉方向，同时让玩家能像观察 WorldBox 一样，持续看到 NPC 在世界中的行动、相遇、冲突与结果。

## 1. 现状判断

当前地图并不是“世界模拟地图”，而是“玩家旅行操作器”：

- `Cosmos → Continent → Region → Venue` 层级已经存在，但 `Region` 只是每个大陆固定的 20×20 六边形展示。
- 玩家移动会直接调用 `moveOneStep`，NPC 大多通过 `locationId → venue → 地标格` 映射，只有少量云游 NPC 有 `hexPos`。
- NPC 的行动主要按月结算；玩家附近没有独立的分钟/小时级运动场景，因此无法持续观察一个 NPC 从家中出发、工作、交谈、冲突再返回。
- 旧节点旅行 API 与六边形旅行 API 并存，距离、时间和事件概率没有统一口径。
- 地图格点击同时承担“选择”和“移动”，造成误触；沿途事件旧概率最高约 42%，自动寻路容易被连续打断。

## 2. 已落地的止血修复

- 区域地图左键改为只选择格子，右键或“前往此处”才发起移动。
- 地图拖动设置 6px 阈值，并吞掉拖动结束后的 click，避免平移误触移动。
- 沿途事件改为按地形单次抽取，概率控制在 0–17%，城镇和虚空不触发随机事件。
- 事件仍然坚持“单步最多一个”，重大世界事件不由沿途随机格子制造。

这些是交互和概率层修复，不代表地图模拟已经完成。

## 3. 核心架构决策

### 3.1 地图是分层流式世界，不做一张无限细节大图

保留现有四层，但重新定义职责：

1. **星界/大陆层**：只表达宏观地理、势力、道路、传送和距离，不运行每个 NPC 的细节动画。
2. **区域层**：以玩家为中心加载有限半径的局部地形块，地形块是可滚动、可扩展的空间，不再把整块大陆压缩成固定 20×20。
3. **聚落层**：城镇、宗门、坊市使用独立的可观察局部地图，具备街区、建筑、道路和人群位置。
4. **场所层**：酒楼、百宝阁、民居等是 NPC 行为和社交的高密度场景。

玩家看到的是“当前焦点周围的真实空间”；世界并不需要把所有大陆都以同样精度绘制出来。

### 3.2 权威状态与渲染状态分离

- `WorldState/NpcRecord` 是权威事实：位置、目的地、行动、关系、伤势、物品、记忆和时间戳。
- 地图上的点、路径、动画和视野是可重建的渲染快照，不写回权威状态。
- NPC 位置不再只由 `locationId` 推导；需要增加“当前区域/坐标、移动目标、路径进度、预计到达时间”。
- 场所仍可作为锚点，但 NPC 离开场所后必须拥有连续的途中位置，而不是瞬移到下一个场所。

### 3.3 三档模拟精度

用“焦点泡泡”平衡 WorldBox 式可见性与性能：

- **世界档**：远离玩家的 NPC 按日或月结算，只保留行动结果和重要事实。
- **区域档**：玩家所在区域及相邻区域按小时/数分钟推进，NPC 位置、路线和偶遇可被观察。
- **焦点档**：玩家选中的 NPC 或当前场景按分钟推进，启用完整大脑节点、社交、偷袭、战斗前置和对话。

降档不能抹掉事实；升档时由权威状态重建中间过程。玩家快速移动时只改变焦点，不改变世界时钟。

## 4. 时间与移动

统一使用 `WorldClockService`：

- 距离是地图数据，速度由境界、地形、负重、功法和状态共同决定。
- 移动耗时使用“距离 ÷ 速度”换算为分钟，再回写世界时钟。
- 普通推进、闭关、旅行和快进都走同一个时间入口；快进只是批量推进，不是另一个时间系统。
- NPC 在移动途中按时间片更新位置；到达、相遇、错过和遭遇都由时间与空间共同决定。

## 5. 事件与战斗入口

沿途随机事件只负责低成本环境噪声和少量机会，不再承担世界剧情：

- 每段移动最多一个可打断事件。
- 事件由区域危险度、生态密度、当前时间、NPC 路线和玩家状态共同计算。
- 普通发现写入日志；战斗、偷袭、重大相遇才弹出交互卡。
- NPC 对 NPC 的冲突先产生“意图/遭遇”，再由战斗解析器决定是否真正开战；不把每次相遇都强制变成战斗。
- 所有重要事件写入事实链，随后才生成叙事文本。

## 6. UI 观察方式

区域地图应提供三种视图，而不是只显示一个玩家光标：

- **世界视图**：势力、聚落、道路和 NPC 密度聚合。
- **区域视图**：可见 NPC 的位置、移动方向、当前行动和状态图标。
- **选中视图**：右侧或底部打开该 NPC 的“修仙大脑”，显示需求、目标、计划、关系、当前行动和可开关节点。

左键永远是选择/检查；右键或明确按钮才是移动/交互。拖动只平移，滚轮只缩放或切换观察半径。

## 7. 分阶段实施

### M1：交互与事件止血（本轮）

- 左键选择与移动解耦。
- 拖动 click 抑制。
- 沿途事件概率分层并注入 RNG。

### M2：统一移动事实

- 定义统一的 `WorldPosition/TravelState`。
- 将节点旅行和六边形旅行收敛到同一时间、距离、速度接口。
- NPC 移动从“场所锚定”升级为“路线 + 连续进度”。

### M3：区域焦点泡泡

- 玩家附近区域按小时或分钟推进。
- 地图显示 NPC 当前行动、路径和局部相遇。
- 远处 NPC 保持低频结算，升档可重建。

### M4：聚落局部地图

- 天机城、宗门、坊市各自拥有局部道路与建筑布局。
- 进入聚落后显示当前 NPC 列表、所在街区和行动状态。
- 百宝阁、酒楼等场所成为社交/交易/冲突的真实空间入口。

### M5：大脑与事件融合

- 选中 NPC 展开完整大脑节点。
- AI 只在高价值 NPC、关键决策和自由度请求时介入。
- 偷袭、背叛、交易和 NPC 战斗统一走意图 → 解析 → 事实 → 叙事链。

## 8. 不变量与验收标准

- 任何 UI 点击不能在未明确发出移动意图时消耗时间。
- 所有移动都能解释为距离、速度和时间的结果。
- 同一 NPC 在地图、场所、战斗和存档中的位置事实一致。
- 快进不会跳过已承诺的 NPC 行动，也不会重复结算事件。
- 远处模拟降精度，但不能凭空改变 NPC 的关系、物品、伤势和死亡事实。
- 玩家观察同一 NPC 时，能看到至少“当前位置 → 当前行动 → 目标 → 下一次状态变化”的连续链路。
