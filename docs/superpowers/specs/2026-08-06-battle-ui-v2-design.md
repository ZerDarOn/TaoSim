# 战斗 UI v2 设计文档

> **状态**：设计已确认（2026-08-06）
> **范围**：战斗界面（BattleOverlay）的人性化重构——命令菜单交互、地图缩放平移、范围高亮、行动顺序预告、飘字反馈
> **边界**：仅 UI 层重构，不修改战斗引擎（BattleEngine v2 / CombatEngine）

---

## 1. 背景与目标

### 1.1 现状问题

当前战斗 UI（`apps/taosim-ui/src/game/BattleOverlay.vue`）由"全屏遮罩 + 左侧 HexCanvas 地图 + 右侧面板"组成，存在以下人性化缺陷：

1. **无普攻/防御入口**：攻击只能通过技能面板选技能；角色无技能时 `availableSkills` 为空，玩家无法造成伤害，只能移动+结束回合（"永不软锁最小动作集"未上 UI）。
2. **无范围可视化**：HexCanvas 不高亮可移动/可攻击格，玩家不知道"能走哪、能打谁"，全凭目测。
3. **无行动顺序预告**：等待期不知道"在等谁行动"。
4. **无技能信息**：技能按钮只有名字+AP，无射程/冷却/灵力/描述。
5. **无结果反馈**：伤害只进文本日志，无飘字、无暴击/闪避/格挡视觉区分。
6. **地图不可缩放/平移**：固定视口，大地图时局促。

### 1.2 设计目标

人性化三问永有答案：

- **"我能做什么？"** —— 命令栏常显，攻击/防御/道具/移动/结束永远可见
- **"我在等谁？"** —— 行动顺序条预告当前行动者与下一位
- **"刚才发生了什么？"** —— 伤害飘字 + 事件播报双通道

参考竞品：FF 系列命令菜单、FFT/火纹范围高亮、FFX CTB 行动顺序条、BG3 动作点与 tooltip。

## 2. 交互模式决策

**采用命令菜单式为主 + 轻量点选融合。**

| 模式 | 优点 | 缺点 |
|------|------|------|
| 命令菜单式（FF） | 动作永远可见、心智简单、对 1v1 最友好、天然对应"永不软锁动作集" | 命令栏占底部空间 |
| 点选单位式（FFT/火纹） | 适合多单位大军团 | 1v1 时多一层无谓的"先点己方" |

决策：

- 底部命令栏**永远可见**（玩家回合激活，NPC 回合置灰显示"等待行动"）。
- **轻量点选融合**：地图上点击敌人 = 直接发起普攻目标选择（省一步）；点击己方 = 显示其信息面板。
- 未来 N vs N 队友加入时，命令栏自动作用于"当前行动单位"，交互模型不变。

## 3. 整体布局

```
┌ 顶部状态条：战斗标题 · 回合数 · 敌我实力对比(境界/人数) ┐
├──────────────────────┬──────────────────────────────────┤
│                      │  行动顺序条（当前行动者+下一位预告）│
│   战斗地图            │  当前行动者卡牌                    │
│   · 滚轮缩放 0.6~2.0x │    名字·境界·HP条·灵力条·AP●●○   │
│   · 拖拽平移          │  命令动作区（技能列表·道具列表）   │
│   · 移动范围高亮(绿)  │   技能tooltip（消耗/射程/冷却/描述）│
│   · 攻击范围高亮(红)  │  战斗事件播报（滚动）              │
│   · 目标悬停/描边     │                                    │
├──────────────────────┴──────────────────────────────────┤
│  命令栏： 攻击 | 技能▾ | 防御 | 道具▾ | 移动 | 结束回合  │
└──────────────────────────────────────────────────────────┘
```

布局原则：

- **左侧地图始终是主视觉区**（flex-1），右侧为固定宽侧栏（约 w-80），底部命令栏常驻。
- 战斗结果弹窗复用现有 BattleOverlay 的 `showResult` 弹窗样式（胜利/惜败/陨落 + 奖励展示 + 继续按钮）。
- 移动端/窄屏降级：命令栏按钮仅保留图标+短文本，侧栏可折叠（Phase B）。

## 4. 地图交互（HexCanvas v2）

### 4.1 缩放与平移

- **缩放**：滚轮以鼠标指针所在像素为中心缩放，范围 `0.6x ~ 2.0x`（`HEX_SCALE_MIN/MAX`）。
- **平移**：按住空白区域拖拽平移；判定规则：pointerdown 后位移超过阈值（`DRAG_THRESHOLD = 6px`）视为拖拽，否则视为点击格子。
- **控制按钮**：地图左下角悬浮 `+` / `−` / `重置`（1.0x，居中）三个按钮。
- **实现要点**（PixiJS）：引入 `viewX/viewY/scale` 三层状态，所有格子像素坐标 = `hexToPixel(q,r) + viewOffset`，绘制时按 scale 缩放；点击换算：`(local - viewOffset) / scale` 反算格子。缩放围绕指针：`newOffset = pointer - (pointer - oldOffset) * (newScale / oldScale)`。

### 4.2 范围高亮

| 模式 | 高亮 | 颜色 | 数据来源 |
|------|------|------|----------|
| 移动（moving） | 当前单位可达格 | 绿色半透明填充（`0x22c55e, 0.35`） | 前端 BFS（复用 `hexNeighbors`/`hexDistance`，步数上限=移动池） |
| 攻击/技能（targeting） | 射程内可攻击目标格 | 红色半透明填充（`0xef4444, 0.35`） | 前端 `hexDistance(actor, tile) <= range` |
| 目标悬停 | 目标格描边 | 白色描边（2px） | pointermove 最近格 |
| 目标选中 | 目标格描边 | 金色描边（3px） | 点击确认 |

- 高亮绘制在独立 Graphics 层（在地形之下、单位之上），随 render 重建。
- 高亮期间点击非高亮格：显示飘字提示（如"超出射程"），**不退出选择状态**。

### 4.3 单位棋子与信息

- 棋子维持现状：圆底 + 名字首字 + HP 条（颜色分级）。
- 悬停任意角色格：浮动详情（名称 / 境界名 / HP / 状态效果图标占位）。
- 选中目标：金色描边。

## 5. 命令栏交互流程（状态机）

### 5.1 状态机 `useBattleUI`

```
idle ──(轮到我)──> command ──> targeting(attack|skill|item) ──> executing ──> idle
                      │             └─(Esc/右键/取消)──> command
                      └─> moving ──> executing ──> idle
```

| 状态 | 含义 |
|------|------|
| `idle` | 非玩家回合 / 战斗未开始 |
| `command` | 玩家回合，命令栏激活 |
| `targeting-attack` | 普攻目标选择（范围=1，高亮射程内敌人） |
| `targeting-skill` | 技能目标选择（范围=技能射程） |
| `targeting-item` | 道具目标选择（己方/敌方） |
| `moving` | 移动目标选择（高亮可达格） |
| `executing` | 命令执行结算中（短暂） |

### 5.2 命令动作定义

| 动作 | 交互 | 结果 |
|------|------|------|
| 攻击 | 点命令 → targeting-attack → 点目标 | 普攻结算 |
| 技能▾ | 展开子列表 → 选技能（tooltip）→ targeting-skill → 点目标 | 技能结算 |
| 防御 | 点命令（无目标选择） | +1 AP（封顶），结束回合 |
| 道具▾ | 展开子列表 → 选道具 → targeting-item → 点目标 | 道具使用 |
| 移动 | 点命令 → moving → 点可达格 | 移动到落点，消耗移动池，**不结束回合** |
| 结束回合 | 点命令 | 结算，交还 ATB |

### 5.3 可取消性

- 所有 `targeting*` / `moving` 状态可随时取消：Esc 键 / 右键 / 面板"取消"按钮 → 回 `command`。
- 点击自身所在格 = 取消移动。
- 命令栏在非玩家回合置灰，中央显示"等待 XXX 行动…"。

### 5.4 与旧引擎的接线（本次实现）

不修改引擎，`useBattleUI` 在现有 `useCombat` 之上封装：

- `attack` → 新增 `useCombat.basicAttack(targetId)`：普攻结算（射程 1、系数 1.0、消耗 1 AP，复用 `DamagePipeline.calculate`，传入内置普攻 Skill 常量 `BASIC_ATTACK_SKILL`）
- `defend` → 新增 `useCombat.defend()`：回 1 AP（封顶）并结束回合
- `skill` / `item` / `move` / `endTurn` → 复用现有 `selectSkill` / `attackTarget` / `movePlayer` / `endTurn`

## 6. 人性化反馈

### 6.1 行动顺序条（升级 ATBBar → TurnOrderBar）

- 顶部：当前行动者卡（高亮金色描边），下方预告下 1–2 位行动者（按 ATB gauge 降序）。
- 每项：名字 + HP 迷你条 + 就绪标记。
- 等待期文案："等待 XXX 行动…"（NPC）/"轮到你行动"（玩家，命令栏激活）。

### 6.2 当前行动者卡牌（BattleStatusPanel）

- 名字 + 境界名（复用 realm 显示映射）。
- HP 大进度条（>50% 绿 / >25% 橙 / ≤25% 红）。
- 灵力条。
- AP 点数：`●●○`（满 3 点）。
- 状态效果图标占位（Phase B 接入 StatusType）。

### 6.3 技能 tooltip

- 悬浮技能按钮显示：名称 / 类型 / AP / 灵力 / 射程 / 冷却回合 / 描述。
- 冷却中：按钮置灰 + 角标显示剩余回合；灵力/AP 不足：置灰。
- 技能按钮布局：网格两列，名称 + AP 角标。

### 6.4 目标悬停详情

- 悬停角色格 → 浮动详情卡片（名称 / 境界 / HP / 状态）。
- 选中目标 → 金色描边（见 4.2）。

### 6.5 伤害飘字

- 结算后在目标格上方生成飘字：`-123`（白/黄），暴击金色放大 `暴击 -246`，闪避灰字"闪避"，格挡蓝字"格挡"。
- 动画：垂直上飘 40px + 淡出，总时长约 1.2s，同一格多飘字错开 0.3s 起始。
- 飘字图层独立于地图，随地图缩放平移。

### 6.6 事件播报（BattleLog）

- 右侧滚动播报，与飘字同源：`张三 对 李四 造成 123 点伤害`、`李四 已被击败`、`李四 防御，回复 1 点行动力`。
- 保留最近 N=200 条，自动滚动到底。

## 7. 组件拆分

| 组件 | 类型 | 职责 |
|------|------|------|
| `BattleOverlay.vue` | 重构 | 布局容器、战斗结果弹窗、接线 useBattleUI |
| `BattleCommandBar.vue` | 新建 | 底部命令栏 + 技能/道具子菜单 |
| `BattleStatusPanel.vue` | 新建 | 当前行动者卡牌 + 行动顺序条（替代 ATBBar） |
| `HexCanvas.vue` | 增强 | 缩放/平移/范围高亮/悬停/飘字 |
| `SkillPanel.vue` | 重构 | 并入命令栏子菜单、tooltip、冷却态（或保留为右侧动作区） |
| `BattleLog.vue` | 新建 | 事件播报滚动（替代内联日志区） |
| `useBattleUI.ts` | 新建 | 战斗 UI 状态机（composable） |

依赖关系：`BattleOverlay → useBattleUI → useCombat → CombatEngine`；`BattleOverlay → HexCanvas/BattleCommandBar/BattleStatusPanel/BattleLog`。

## 8. 数据流

```
BattleOverlay
  │ useBattleUI(phase, action)
  ▼
useBattleUI ──> useCombat.movePlayer / selectSkill / attackTarget / basicAttack / defend / endTurn
  │                 ▼
  ▼              CombatEngine（唯一写入者）
HexCanvas ◄── 高亮数据(可达格/攻击范围) + 单位位置/HP + 飘字事件
BattleStatusPanel ◄── 当前行动者/ATB/预告
BattleLog ◄── 事件流
```

- 高亮数据（移动范围/攻击范围）由 `useBattleUI` 计算后作为 props 传入 HexCanvas。
- 飘字事件由 `useBattleUI` 在命令结算后推入 HexCanvas 飘字队列（事件总线或 props+emit）。
- 本次不接 BattleEngine v2 的 BattleDelta/事件系统；Phase B 替换数据源时接口不变（见 §9）。

## 10. 验收标准

- [ ] 玩家回合命令栏常显，六动作均可操作；NPC 回合置灰显示"等待 XXX 行动…"
- [ ] 普攻：射程 1 结算，暴击/闪避/格挡有飘字区分；无技能角色可正常造成伤害
- [ ] 防御：回 1 AP 并结束回合
- [ ] 移动：绿色高亮可达格，点击落点不结束回合，Esc/点击自身可取消
- [ ] 技能：tooltip 完整，冷却/资源不足置灰；目标选择高亮射程内目标
- [ ] 地图：滚轮缩放 0.6–2.0x（围绕指针）、拖拽平移、+/−/重置按钮；点击与拖拽正确区分
- [ ] 行动顺序条预告下一位；当前行动者卡牌显示 HP/灵力/AP
- [ ] 悬停目标显示详情；事件播报滚动正常
- [ ] 原有战斗流程（胜负判定/奖励/GameOver）无回归
